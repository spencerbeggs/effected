# Decision

* [@effect/platform-node is a required peer in exactly one package](platform-node-peer-in-one-package.md) - github-actions is the only kit package with a required @effect/platform-node peer, because a GitHub Action always compiles into one Node process on a GitHub-provided runner; the licence is scoped to that overlay and does not generalize to any other package.
* [@effected/cli grows a presentation layer and interactive UI](cli-grows-presentation-layer.md) - @effected/cli takes on audience, interactivity, theme, status vocabulary, messages, the document IR, failure rendering and logging composition in its React-free root, and interactive screens behind ./ui, replacing the not-a-framework limitation's ban on prompts and spinners.
* [@effected/env is its own boundary package, a required peer of cli](env-is-its-own-package.md) - Audience and terminal detection live in a dedicated @effected/env package that @effected/cli requires as a peer; only the --audience flag lives in cli, so MCP servers and engines detect without a CLI dependency.
* [@effected/github owns the octokit runtime](github-owns-octokit-runtime.md) - Why the octokit client and the sealed-box crypto pair live in @effected/github rather than being pushed to consumers.
* [@effected/schema-org declines both available @effected edges](schema-org-declines-kit-edges.md) - license and version are typed to the vocabulary's own wide ranges rather than to @effected/spdx or @effected/semver, because a vocabulary's declared range is the contract.
* [@effected/vfs is deferred until a second consumer materializes](vfs-deferred-until-second-consumer.md) - A generic node\_modules/-prefixed virtual filesystem with merge/prefix helpers and an environment seam is decided-but-unbuilt; it ships only when a second VFS consumer appears beyond the TypeScript-tooling one that motivated its shape, never speculatively.
* [A live view is a scoped drain of runs, hosted or owned, with no input and the mount permit per run](live-view-runs-and-modes.md) - CliUi.live folds a Stream into state inside the caller's scope; a run begins at an isStart event (or where an optional begins predicate says, given the state before and after) and ends at an isTerminal event, which unmounts and commits the frame, and an event outside a run that begins none is folded and not drawn; hosted and owned differ only when not interactive, neither mounts input hooks, and interactive is passed explicitly rather than left to Ink's is-in-ci guess.
* [A lockfile is a YAML stream, not always one document](lockfile-is-a-yaml-stream.md) - pnpm lockfiles using config dependencies are two YAML documents in one file, and lockfiles is parsed against that fact by position rather than by content heuristic.
* [A physical ascend ceiling is a separate static taking an Option, not a realpath mode of stopAt](physical-ceiling-is-a-separate-static.md) - Walker.ascendWithin bounds the upward walk by a symlink-resolved ceiling as its own static, so ascend's R stays Path alone, and takes the ceiling as an Option so a stray undefined cannot request an unbounded walk.
* [A schema.org property gets one fixed arity, chosen toward many when uncertain](schema-org-property-arity-declines-collapse.md) - Every modeled property is either always a scalar or always an array, never a union of the two, and an uncertain case is modeled as an array because the two error costs are asymmetric.
* [A schemastore outputDir is never exclusively the CLI's](output-dir-is-never-exclusively-owned.md) - schemastore-cli reads only the paths it derives, never a listing of outputDir, because that directory may be shared with another config, a deploy folder, or the repository root — so orphan detection probes derived sibling shapes and knowingly misses a name change.
* [A second published entrypoint is a measured cost, not a convenience](second-published-entrypoint.md) - A package adds a subpath export only when a structural test proves an unbundled consumer would otherwise pay to load a part of the graph it never touches.
* [A test needing FileSystem uses memfs, never a hand-rolled layerNoop stub](memfs-over-layernoop.md) - Migrate every test's filesystem double from FileSystem.layerNoop to @effected/memfs, because a hand-rolled stub only encodes the semantics its author remembered.
* [Azure is confined to three modules, not two](azure-blob-confined-to-three-modules.md) - The Azure blob client may only be imported by ActionCache, Artifact and BlobStore.githubCache — not by any shared internal helper.
* [Carrier-only bins are recommended; shared bins are a supported choice](carrier-only-declares-bins.md) - In the carrier pattern, front ends should declare no bin of the carrier's names, required only when provenance must hold under flat installs; sharing the names is a supported choice with allowSharedBins, and PackedInstall's BinConflict default makes it explicit.
* [CliLinks finds the editor directory with its own bounded ascent](cli-links-inline-ascent.md) - CliLinks walks up to find a .vscode directory with an inline Path.dirname loop over FileSystem.exists, rather than depending on @effected/walker, which would add @effected/glob to every cli consumer's closure.
* [CliLinks finds the project root with @effected/walker](cli-takes-the-walker-edge.md) - CliLinks locates the nearest ancestor holding .git or pnpm-workspace.yaml with Walker.ascend and Walker.findRoot, taking @effected/walker as a required peer of @effected/cli, rather than a hand-written ascent.
* [CliLogger honours LogToStderr only as a force-all override](cli-logger-force-all-stderr-only.md) - Why the public LogToStderr reference can only push every level to stderr, never move one level back to stdout.
* [ConfigCodec is exempt from the sync primitive policy](codecs-exempt-from-sync-primitive-policy.md) - A ConfigCodec's Effect-returning members are not required to carry a synchronous Result twin, because their Effect return type expresses interface polymorphism, not a wrapped span.
* [Contract inversion is the default answer to a tier-dragging edge](contract-inversion-default.md) - When package A needs behaviour only package B can implement, A declares the narrow contract and B ships the layer implementing it, rather than A taking a direct dependency edge on B — the pattern now runs three times across the kit.
* [D10: McpToolAudit enforces object-rooted outputs by default](mcp-tool-audit-object-rooted-outputs.md) - McpToolAudit.check's objectRootedOutput policy defaults to true, flagging a tool whose declared output can be a bare scalar or array, because the stateless 2026-07-28 adapter passes a non-object output through verbatim.
* [D1: @effected/engine exists and holds Distribution, Remediation and LaunchContext](engine-holds-cross-front-end-primitives.md) - A new pure-tier package sits below @effected/cli and @effected/mcp so a consumer's own engine can stamp distribution without depending on a front end.
* [D2: strict MCP input is upstream-first](mcp-strict-input-upstream-first.md) - Ship pure ToolInputSchema walkers now, and add an McpToolkit decorator only if probe P1 proves the registerToolkit port round-trips; do not consolidate a full port into the kit.
* [D3: CliLogger's stderrFrom default flips to All](cli-logger-defaults-all-to-stderr.md) - Every log level now routes to stderr by default, so a CLI's stdout carries only what the program writes with Console.log — a breaking 0.x change closing
* [D4: okfit and vitest-agent are registered as consumers before extraction](register-consumers-before-extraction.md) - Consumer concepts are written and linked before any engine/cli/mcp primitive is extracted from their repos, so every extraction is justified against a recorded survey rather than memory.
* [D5: the layering, packed-install and boundary checks live in @effected/workspaces/testing](repo-shape-checks-live-in-workspaces-testing.md) - WorkspaceLayering, PackedInstall and SourceBoundary join a new testing subpath on the existing integrated-tier workspaces package rather than a dedicated package or an engine/testing subpath.
* [D6: CLI and MCP knowledge stays in separate skills, linked from design-patterns](front-end-skills-stay-separate.md) - effect-v4-cli and the new effect-v4-mcp stay independent skills rather than folding into design-patterns, which points at both instead of teaching either surface itself.
* [D7: usageExitCode defaults to 64 (BSD EX\_USAGE)](usage-exit-code-defaults-to-64.md) - A ShowHelp carrying errors remaps to exit 64 by default rather than core's 1, giving a usage error a distinct, greppable code from an ordinary program failure.
* [D8: CliColor ignores FORCE\_COLOR, matching core](cli-color-ignores-force-color.md) - CliColor.enabled reads only Stdio.stdoutIsTerminal and a non-empty NO\_COLOR, deliberately leaving FORCE\_COLOR unhandled everywhere, consistent with core's own colour decision.
* [D9: CliTest uses core ChildProcess, with no peer on @effected/commands](cli-testing-uses-core-child-process.md) - The new @effected/cli/testing subpath spawns fixture binaries directly over effect core's ChildProcess contract rather than adding an optional peer on @effected/commands.
* [D: strict MCP input default for Claude Code](mcp-strict-default-for-claude-code.md) - McpToolkit.layer's DEFAULT\_STRICT is "all" — every tool without its own Tool.Strict annotation is served and decoded strict — because probe P2 found Claude Code 2.1.281 never places its own protocol extras inside a tool call's arguments.
* [Decided against: a shared @effected/errors package](no-shared-errors-package.md) - A cross-package errors package was rejected for four reasons — the kit already has a shared error vocabulary in effect core, a central errors package inverts ownership and couples every error change to a cross-package release, Effect's error channel already composes unions structurally, and the genuine cross-boundary case already has a house pattern.
* [Each format package keeps its own options type](format-options-type.md) - No shared kit-wide formatter options shape; each package's options stay irreducibly format-specific.
* [Each plugin versions via its own private tracking package](plugins-version-via-private-tracking-packages.md) - Both plugins version and release independently of the kit's library waves, each through a private, never-published workspace package that exists only to give changesets something to version.
* [Each runtimes resolver exposes three lazy layer constants, not one configurable layer](cache-strategy-as-layer.md) - layer/layerFresh/layerOffline are memoized layer constants over a run-once population gate, never Effect.cached and never a fetch inside Layer.effect.
* [Every default reference time comes from Clock, never new Date()](runtimes-wall-clock-via-clock.md) - Phase logic reads DateTime.now so TestClock can drive it deterministically; no member reaches for the ambient wall clock directly.
* [FORCE\_COLOR is honoured, with Node's getColorDepth precedence](force-color-honoured-node-precedence.md) - @effected/env reads FORCE\_COLOR ahead of NO\_COLOR, NODE\_DISABLE\_COLORS, TERM=dumb and the TTY gate, in the order Node's tty getColorDepth uses, replacing the kit's earlier decision to ignore it.
* [Format entry points never return Effect](format-return-type.md) - A three-way return-type rule keyed on whether failure is possible; a tolerant formatter entry point never returns Effect.
* [Format-package naming is \`\*Format\`, not \`\*Unvalidated\`](format-naming.md) - The \`\*Format\` concept class with total statics is the kit's naming convention; \`\*Unvalidated\` is rejected.
* [Generated objects are closed by default, departing from core's open default](schemastore-closed-objects-by-default.md) - StoreDocument.fromSchema generates with onExcessProperty: error so every object is emitted with additionalProperties false, because a published document is a contract; core's own default flipped open at rc.113 and the package no longer follows it.
* [Git failure classification happens once, in one private function](git-classification-happens-once.md) - No consumer of @effected/git ever string-matches stderr; a single private classify step in Git.ts is the only place that inspects stderr, stdout or exitCode.
* [GitHubClient keeps only the authenticated REST reads Bun and Deno need](runtimes-githubclient-honestly-scoped.md) - Shared JSON-over-HTTP machinery lives in internal/http.ts, used unauthenticated by the Node fetchers and authenticated by GitHubClient, over one shared HTTP error family.
* [Markdown dialects are a closed set with no public extension API](markdown-dialects-closed-set.md) - @effected/markdown exposes a dialect option (CommonMark or GFM) with no plugin mechanism, matching the yaml and toml packages' zero-plugin posture.
* [Markdown editing is offset-splice, not a lossless CST](markdown-editing-is-offset-splice.md) - @effected/markdown edits source via offset/length/content splices over the original text, matching the jsonc/yaml/toml edit vocabulary, rather than a lossless concrete syntax tree.
* [No SchemaVersioning.plan surface](schemastore-no-versioning-plan-surface.md) - SchemaVersioning ships no separate planning function, because catalogUrls already sorts and dedupes the version set a plan would compute.
* [No bin on the library — the CLI is a fixed-version companion package](schemastore-no-bin.md) - @effected/schemastore ships no bin entry; the schemastore executable lives in @effected/schemastore-cli, a bin-only companion released in a fixed group with the library.
* [No layerDefault on SchemaValidator or SchemaFile](schemastore-no-layer-default.md) - Every service-shaped module ships a real layer and a test layer; a third layerDefault would only be a name for one of the two that already exist.
* [No shipped templates/ directory](schemastore-no-shipped-templates-directory.md) - The bundler publishes only emitted src, LICENSE and README; the canonical schema-generator script a consumer copies lives outside the package.
* [One tracking package versions both plugin builds](ai-plugin-versions-both-builds.md) - @effected/ai-plugin, a private never-published workspace package, versions the Claude Code and Copilot builds together, so one changeset releases both at one version.
* [Only ./ui may bind Node's process streams, and only in three named files](ui-binds-process-streams.md) - @effected/cli/ui alone may rely on Node's process streams, because Ink has exactly one platform shape; the licence is file-scoped to processStreams.ts, inkChalk.ts and the testing-only fakeStreams.ts, and does not generalize the platform-node licence.
* [Only package-json needs a tolerant formatting seam](format-tolerant-seam.md) - package-json is the one format package that adds a tolerant entry point; the other four and config-file add no new surface.
* [PackedInstall packs the prod npm directory by default](packed-install-pack-source.md) - Probe P3 compared pnpm-packing a package's source against npm-packing its dist/prod/npm/pkg build, and PackedInstall's default packFrom became { directory: "dist/prod/npm/pkg" }.
* [Provenance lives in the engine state, and is never hardcoded](runtimes-provenance-in-engine-state.md) - The release index carries a live/cache source marker set by whichever strategy actually populated it, so a stale snapshot is never reported as fresh.
* [Releases are changeset-driven and scope-agnostic](release-model.md) - CI builds the changesets present on a branch and releases exactly the packages they name — a whole-kit wave and a single-package patch are the same mechanism, every package stays 0.x and unstable until the kit chooses 1.0.0, which stable Effect v4 makes possible rather than automatic, and breaking changes ride minors.
* [SchemaFile's write-if-changed compares parsed content, not bytes](schemastore-write-if-changed-compares-content.md) - Content comparison is the default for write-if-changed, with byte-exact comparison an opt-out, because a repo that formats its JSON makes byte comparison never converge.
* [SchemaStore's own coverage tool is not reimplemented](schemastore-coverage-tool-not-reimplemented.md) - The package treats SchemaStore's own coverage checks as candidate inspiration only, rather than reimplementing them as a shipped feature.
* [Schemastore retiers from boundary to integrated for a direct ajv dependency](schemastore-retier-to-integrated.md) - The one package in the kit retiered after publishing, from boundary to integrated, to take ajv as a real validation engine rather than a contract-only seam.
* [Store is built on effect's own SQL core and @effect/sql-sqlite-node](store-v4-sqlite.md) - Store uses the SqlClient abstraction shipped inside effect core plus the Node sqlite driver, and hand-rolls its own reversible migration ledger rather than core's forward-only Migrator.
* [Store is named for its primitive, not its backend](store-named-for-primitive.md) - The package name and public surface describe a schema-versioned migrated SqlClient and a TTL cache — nouns any SQL driver could satisfy — never the specific SQLite implementation behind them today.
* [Strict MCP input is reported by core; McpToolkit appends the accepted params instead of pre-checking](mcp-strict-input-reported-by-core.md) - Core's strict tool decode reports every unknown key, missing field and invalid field in one InvalidParams, so McpToolkit.layer drops its unknown-key pre-check and instead appends an Accepted params line per offending level to core's report, unionHandler decodes with errors: "all" and appends the same lines, and ToolInputSchema stays public for Tool.dynamic payloads.
* [The Draft-07 meta-schema constant keeps its trailing hash](schemastore-meta-schema-keeps-trailing-hash.md) - DRAFT\_07\_META\_SCHEMA carries a trailing hash, matching the SchemaStore corpus convention and deliberately diverging from core's equivalent constant.
* [The Ink layer is a ./ui subpath of cli, with ink and react as optional peers](ui-is-a-subpath-with-optional-peers.md) - Interactive screens live in @effected/cli behind ./ui and ./ui/testing, with ink and react as optional peers that the root never reaches and that ./ui itself loads only when a screen mounts; separate cli-ink and cli-ui packages were rejected.
* [The MDX brace escape is presence-keyed, never a stringify option](markdown-mdx-escape-presence-keyed.md) - A tree carrying any MDX node additionally escapes { in text; the escape is triggered by a pre-scan of the tree, never by a caller-set option.
* [The NTIA minimum-elements report is a report, not a gate](ntia-report-not-a-gate.md) - NtiaReport is a pure function returning a compliance report; the caller decides whether non-compliance fails a run.
* [The Node schedule is keyed by release line, not by major](runtimes-node-schedule-by-release-line.md) - NodeScheduleEntry carries a line string ("20", "0.10") rather than a numeric major, because early Node majors collapse under Number.parseInt.
* [The ajv engine lives in the CLI, and the library returns to boundary tier](schemastore-engine-lives-in-the-cli.md) - The one shipped SchemaValidator engine is @effected/schemastore-cli's AjvValidator.layer — and the one shipped InstanceValidator engine its AjvInstanceValidator.layer — so ajv is a cost only the command pays; @effected/schemastore keeps the contracts and their doubles, drops ajv and ajv-formats, and retiers from integrated back to boundary.
* [The ascend ceiling compares resolved paths and rejects a relative stopAt as a defect](ascend-ceiling-fails-closed.md) - Walker's ascend ceiling normalizes both sides before comparing and dies on a relative stopAt, closing a fail-open bug where an unnormalized ceiling silently let the scan reach the filesystem root.
* [The assembly module is named StoreDocument, not SchemaDocument](schemastore-module-naming-storedocument.md) - Naming the assembly module StoreDocument rather than SchemaDocument, to avoid a name that reads like the banned general-JSON-Schema scope.
* [The audience flag is four shared root flags resolved into env's Audience](audience-flag-is-shared-root-flags.md) - CliAudience declares --audience, --human, --agent and --ci as shared flags on the root command, each counted with Flag.atLeast(0), and resolves them with Command.provideEffect into env's Audience with source flag; more than one occurrence is a usage error.
* [The cli package owns its display-width function](own-display-width.md) - Fmt measures display width with a short Intl.Segmenter plus emoji and East Asian Width range implementation checked by a differential test against string-width as a devDependency, rather than declaring string-width at runtime.
* [The cli renderers have no JSON output](no-json-renderer.md) - Render ships plain, ANSI, markdown and GitHub-log renderers and no JSON renderer, because both consumers encode their own schemas and JSON is data, not a rendering of a document.
* [The cli root boundary is a module-graph walk, not a per-file scan](root-boundary-is-reachability.md) - boundary.test.ts proves the root never reaches ./ui by walking the import graph from src/index.ts and src/testing.ts, because SourceBoundary.scan checks files one at a time and missed a root file importing a ui module (probe P4).
* [The cli root stays boundary, and ./ui is integrated only for consumers who opt in](ui-tier-is-integrated-on-opt-in.md) - @effected/cli keeps a boundary-tier root while its ./ui subpath imports the third-party ink and react, which makes ./ui integrated only for a consumer who installs those optional peers; R1-R4 are read per entrypoint for this package.
* [The config companion is named @effected/plugin, not built yet](config-companion-named-effected-plugin.md) - A future silk-pattern companion package will ship config JSON files and peer-depend on the mcp/cli tools so a consumer's Claude Code plugin and tooling stay on the same versions; the name @effected/plugin is decided, @effected/config is rejected as confusable with @effected/config-file, and the package itself is unbuilt.
* [The config-driven GitHub auth layer reads Config, never process.env](runtimes-config-not-process-env.md) - Token resolution uses Config with a documented precedence between two conventional environment variables, warns on ambiguity, and holds the token Redacted.
* [The document IR is plain frozen data, not Schema classes](doc-ir-is-plain-data.md) - The cli document IR is an immutable union of plain objects discriminated by \_tag, built by constructors and rendered by pure (doc, context) =\> string functions, rather than Schema classes or React elements.
* [The effect catalog pins exact versions](effect-catalog-exact-pins.md) - The Effect catalogs pin exact prerelease versions with no caret, never a range.
* [The effect catalog takes caret ranges on the stable line](effect-catalog-tracks-stable-minor.md) - With Effect v4 stable, the effect and effect:peers catalogs give effect and every @effect/\* package a caret range under lock-minor; the lockfile, not the catalog literal, fixes the exact version, and .repos/effect follows the lockfile.
* [The effected catalog holds next-release versions, and the publish order follows](catalog-holds-next-release-versions.md) - The effected catalog literal resolves each package's next published version rather than its current registry version, which imposes the publish order changesets → catalog:sync → publish and is enforced by a workflow that triggers on pull requests to changeset-release/main.
* [The fidelity obligation and how it is tested](format-fidelity-obligation.md) - A kit formatter changes only key order, whitespace and the trailing newline, and Direction B round-trip testing is what proves it.
* [The git ssh BatchMode pin is appended to what git would have used, and declines rather than substitutes](git-ssh-pin-appends-and-declines.md) - Before a network-touching Git member spawns, the service walks git's own GIT\_SSH\_COMMAND \> core.sshCommand \> GIT\_SSH order at that cwd and appends -o BatchMode=yes only where appending is meaningful; every other case leaves the environment unpinned.
* [The jsonl Journal service is a per-registry factory, not a generic key](jsonl-service-is-a-factory.md) - \`Journal.Service\<Self\>()(id, { events, config })\` produces one class per event registry, with its layer a single static value built from the definition-site config.
* [The kit sets Ink's colour level on Ink's own chalk, resolved from Ink's location](ink-colour-via-inks-own-chalk.md) - At mount the kit resolves the chalk that Ink imports, from Ink's own location, sets its level from the stream's ColorLevel and restores it on release; FORCE\_COLOR, a kit chalk dependency and token-only styling were each measured and rejected (probe P2).
* [The kit's layering check forbids runtime edges only](kit-layering-checks-runtime-edges.md) - The front-end kit's forbidden package edges are runtime edges, so this repository's layers.json checks dependencies, peerDependencies and optionalDependencies, and test-only devDependencies may point up.
* [The live frame is clamped to rows - 1 in height, and its root width is never taken from a hook](live-height-clamp-not-width.md) - Ink 7.1.1 does not miscount a line exactly columns wide, but a frame taller than the terminal makes Ink emit ESC\[3J and wipe the scrollback, and a root width read from useTerminalSize lags Ink's own resize repaint and strands a copy on shrink; so the clamp is on height, and a margin, if wanted, is marginRight 1.
* [The live view never calls Ink's clear(); a new run re-renders in place or remounts](live-never-clears.md) - Ink's instance.clear() erases the frame but tells log-update the frame is still on screen, so the next differing render erases that many lines of scrollback above it; a start while mounted re-renders in place, a terminal event unmounts to commit the frame, and the next start mounts fresh.
* [The live view's tick is a scoped Effect schedule, and its frame index comes from Clock](live-tick-is-a-scoped-schedule.md) - Each run forks Effect.repeat(push, Schedule.spaced(tickMillis)) into its scope and computes the frame index as floor(Clock.currentTimeMillis / tickMillis), replacing the first design's unref'd native timer; the scope bound lets the process exit at once and TestClock drives every frame.
* [The npm tier guardrail — a non-core runtime dependency in a service escalates the whole package](npm-tier-guardrail.md) - @effected/npm stays boundary only while its pure vocabulary never reaches IO and index.ts exports individually; a reachability test asserts both from the source graph, and the answer to the named escalation trigger is a package split, never an accepted retier.
* [The numeric-enum codec is data, not a typescript dependency](numeric-enum-codec-is-data.md) - TypeScript's enum numeric values live in tsconfig-json as a hand-transcribed data table rather than being imported from the typescript package.
* [The release index is Ref-backed with a single atomic load](runtimes-concurrency-safe-index.md) - An index inconsistency between the release set and its lookup map is treated as a programmer error and stays a defect, never a typed failure.
* [The sync form is named \`\*Result\`, never \`\*Sync\`](sync-form-named-result.md) - The kit spells a pure boundary's synchronous twin \`\*Result\`, reserving \`\*Sync\` for genuinely IO-performing sync facades.
* [The typechecker: tsc, not tsgo](tsc-not-tsgo.md) - Every package's types:check runs tsc --noEmit against catalog:build; @effect/tsgo is never added to a package even though the catalog entry still exists.
* [The ui declarations reference the root's types by the package's own name](ui-declarations-reference-the-root-by-name.md) - The ./ui and ./ui/testing declarations import the root's types from @effected/cli (kept external with dtsExternals) instead of carrying copies, with API Extractor's resulting noise suppressed for the ui entries only and re-pinned by tests over the built declarations.
* [The validation gate ships a real ajv engine, closed by default](schemastore-ajv-ships-closed.md) - SchemaValidator ships a real ajv-backed layer rather than a contract-only seam or a companion package, because a copied adapter is not a shipped default.
* [The workflow-command grammar left github-actions for its own pure package](github-commands-extracted-from-actions.md) - WorkflowCommand and the neutralizer live in the pure @effected/github-commands so a boundary-tier package can neutralize without the integrated github-actions tier and @effect/platform-node.
* [The yaml lint system stays inside the pure tier](yaml-lint-pure-half-only.md) - The lint engine and built-in rules ship in pure-tier @effected/yaml; file discovery, config-file loading, a CLI and autofix-to-disk are explicitly out of scope for the package.
* [There is no Effect v3 catalog and no camelCase catalog alias](effect3-catalogs-retired.md) - The effect3/effect3:peers catalogs and the effectPeers/effect3Peers camelCase aliases are retired and must not be reintroduced.
* [Two prompt engines raise one Cancelled error](one-cancelled-for-two-prompt-engines.md) - Core Prompt and the kit's ./ui screens both surface a single Cancelled tagged error with reason escape or interrupt, carrying exit code 130, so a consumer maps cancellation once.
* [Vendored Effect is pinned to the lockfile's tag, not main](vendored-effect-pinned-to-catalog-tag.md) - .repos/effect tracks the release tag matching the effect the lockfile resolves, not the catalog literal and not the upstream default branch.
* [While a live view is mounted, kit logs go through Ink's own stdout and stderr writers](live-logs-through-ink.md) - The live view exposes a bridged Console whose writes go through Ink's useStdout().write and useStderr().write while a run is mounted, so a log line lands above the frame without tearing it, and straight to the stream before mount and after unmount, since Ink silently drops hook writes after unmount.
* [WorkspacesSync is a \`\*Sync\` escape hatch, not a \`\*Result\` pure form](workspaces-sync-facade-escape-hatch.md) - The synchronous WorkspacesSync facade exists for a caller that cannot await, and it is named \`\*Sync\` rather than \`\*Result\` because it is a total port over consumer-supplied IO, not a pure computation with a sync twin.
* [app is a composition layer, not an umbrella package](app-is-composition-not-umbrella.md) - app defines no service, schema or error of its own and re-exports nothing from xdg, store or config-file -- a consumer wanting one of them alone takes that package alone.
* [cli files the Command handler-accessor gap upstream rather than shimming it](cli-handler-accessor-gap-filed-upstream.md) - Why a missing accessor on effect/cli's Command type is reported to core instead of patched locally.
* [cli sets the exit code through core's own Runtime markers](cli-exit-code-via-runtime-markers.md) - Why CliRuntime.reportFailures reads and writes Runtime.errorExitCode / Runtime.errorReported instead of touching process.exitCode.
* [commands' workspaces edge inverts rather than dragging four packages integrated](commands-workspaces-edge-inverts.md) - Why @effected/commands declares LocalExec instead of depending on @effected/workspaces directly.
