# The effect catalog pins exact versions

## Context

`pnpm-workspace.yaml` declares an `effect` catalog and an `effect:peers` catalog, generated by [`pnpm-plugin-effect`](../modules/pnpm-plugin-effect.md), that every `@effected/*` package and this workspace resolve `effect` from. `.repos/effect` — the vendored Effect v4 source, the authority on what v4 actually exports — is checked out at one release tag at a time. Effect v4 is still on the prerelease line (`4.0.0-rc.*`), and a version is not yet a stable target: prerelease numbers move frequently and a version-range spec resolves differently to different installs at different times.

## Decision

The `effect` and `effect:peers` catalogs pin **exact** prerelease versions — no caret, no range — under a `lock` strategy, so the whole workspace resolves to one pinned version on install, and every published `@effected/*` package advertises that same exact version as its `effect` peer range.

## Alternatives rejected

A caret range on the prerelease (`^4.0.0-rc.115`) was rejected. A caret floats freely across the prerelease release line and would silently desynchronize the installed `effect` from the `.repos/effect` submodule pinned to one tag — an agent could then read vendored source and assert, with source in hand, a surface that does not exist in whatever prerelease actually got installed. That failure is worse than an admitted unknown, because the evidence looks conclusive while being wrong.

## Consequences

Every advance of the pin is a coordinated, kit-wide change: one changeset per package, one wave, because the exact-pin discipline extends to every package's advertised peer range. It also means every advance can strand the previously-published closure on the old exact pin until a bridge is put in place — see the toolchain-bridge shapes recorded under [one resolved effect copy](../conventions/one-resolved-effect-copy.md) and the procedure in [advance the effect pin](../runbooks/advance-the-effect-pin.md). The peers catalog being locked exact (not just the internal `effect` catalog) is what lets a consumer's own install pin the same version the kit was built and tested against.
