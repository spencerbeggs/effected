# `@effected/s3`

`@effected/s3` is the kit's one client for raw objects in an S3-compatible store: AWS S3, Cloudflare R2, MinIO, Spaces. The only S3 transport the kit had was `BlobStore.layerS3` in [`github-actions`](github-actions.md), which frames every object in its own envelope, has no list, and is integrated tier. A service that stores raw objects therefore hand-rolled a client over [`crypto`](crypto.md)'s `SigV4`, and the one that did, `savvy-web/build`'s intake archive, shipped a `ListObjectsV2` parser that read a 200 answer carrying an `<Error>` document or a proxy's HTML page as "no keys".[^issue-1214][^intake-archive][^intake-list] Why a package of its own, and why the listing is strict: [the S3 object client package](../decisions/s3-object-client-package.md).

## Tier and dependencies

Boundary tier, by the owner's ruling.[^owner] `effect` is the only peer; [`@effected/crypto`](crypto.md) is the only dependency, a regular `workspace:^` edge because it carries no shared-instance contract. There is no `node:` import under `src/`, so the client runs on Node, browsers and Cloudflare workerd. Every request goes through core `HttpClient.HttpClient`, and signing needs core `Digest.Digest` and `Mac.Mac` (`effect/crypto`); all three are required in `R` when the layer is built and resolved once there, so every method's `R` is `never`.[^core-http-client] [`@effected/memfs`](memfs.md) is a devDependency of the skeleton and unused by the tests, which need no filesystem.

## Public surface

```ts
interface S3Credentials {
  readonly accessKeyId: Redacted<string>;
  readonly secretAccessKey: Redacted<string>;
  readonly sessionToken?: Redacted<string>;
}

interface S3ClientOptions {
  readonly bucket: string;
  readonly region: string;          // "auto" for R2
  readonly endpoint?: string;       // default https://s3.<region>.amazonaws.com
  readonly credentials: S3Credentials;
  readonly forcePathStyle?: boolean; // default: true with an endpoint, false without
}

class S3Client extends Context.Service<S3Client, S3ClientShape>() {
  static make(options): Effect<S3ClientShape, never, HttpClient | Digest | Mac>;
  static layer(options): Layer<S3Client, never, HttpClient | Digest | Mac>;
}

interface S3ClientShape {
  put(key, body: Uint8Array | string, options?: S3PutOptions): Effect<S3PutResult, S3PutError>;
  get(key, options?: S3GetOptions): Effect<S3Object, S3GetError>;
  head(key): Effect<S3ObjectHead, S3HeadError>;
  delete(key): Effect<void, S3DeleteError>;
  list(options?: S3ListOptions): Effect<S3ListPage, S3ListError>;
  listAll(options?: S3ListAllOptions): Stream<S3ObjectSummary, S3ListError>;
}
```

`S3PutOptions` carries `ifNoneMatch` (`"*"` or an ETag), `ifMatch`, `contentType` and `metadata`; `S3GetOptions` carries `ifNoneMatch` and `range` (a raw `Range` value such as `bytes=0-9`); `S3ListOptions` carries `prefix`, `delimiter`, `startAfter`, `continuationToken` and `maxKeys`. `S3ListAllOptions` is `prefix`, `startAfter` and `maxKeys` (the page size): no `delimiter`, because a stream of object summaries would silently drop the common prefixes a delimiter produces, and no `continuationToken`, because the stream follows them itself.

The results are `Schema.Class` models: `S3PutResult` (`etag`, optional `versionId`), `S3ObjectHead` (`key`, `etag`, `contentLength`, `metadata`, optional `contentType`, `lastModified` and `versionId`), `S3Object` (the head's fields plus `body` and an optional `contentRange`), `S3ObjectSummary` (`key`, `size`, `lastModified`, optional `etag` and `storageClass`) and `S3ListPage` (`keys`, `commonPrefixes`, `isTruncated`, and `nextContinuationToken` as an `Option`). An ETag is kept exactly as S3 sends it, quotes included, so `ifMatch: head.etag` round-trips.

## Behaviour

- **Addressing.** Path style sends `<endpoint><base path>/<bucket>/<key>`; virtual-host style sends `<scheme>://<bucket>.<host>/<key>`. A custom endpoint defaults to path style, which every S3-compatible store accepts; AWS without an endpoint defaults to virtual host, except for a bucket name holding a dot over `https`, which defaults to path style: as a host label it would not match a `*.s3.<region>.amazonaws.com` wildcard certificate and would fail TLS. An explicit `forcePathStyle` is always honoured. An endpoint's own path is kept in front of the bucket. The key is signed unencoded and sent exactly as `SigV4` encoded it, so `!'()*` and non-ASCII keys reach the store as signed.
- **Validation before signing.** A key that is empty, holds a lone UTF-16 surrogate (checked before the length, since `TextEncoder` would count it as U+FFFD and `encodeURIComponent` throws on it inside signing), longer than 1024 UTF-8 bytes, or holds a `.` or `..` segment (which every URL parser collapses) fails with `S3InvalidRequest`, as does a `prefix`, `delimiter`, `startAfter` or `continuationToken` holding a lone surrogate (reason `malformed-unicode`, `field` naming the option; listing options ride in the signed query, so well-formedness is their only rule), as does a string `put` body holding a lone surrogate (`malformed-unicode`, `field` `body`: `TextEncoder` would store U+FFFD in its place without a word; a `Uint8Array` body is sent as given), as does a metadata name that is not an HTTP token, two metadata names that differ only in case (they would be one header), a header value holding a control character, or a `maxKeys` outside 1 to 1000. Nothing is signed or sent. Bad options (an empty bucket, a bucket with `/`, an endpoint that is not an `http:` or `https:` URL, a bucket virtual-host style cannot address) are a wiring mistake and die when the client is made.
- **Timestamps.** A `Last-Modified` header must be an IMF-fixdate (`Thu, 29 Feb 2024 23:59:59 GMT`) whose date and time survive a round trip, and a listing's `LastModified` an ISO 8601 date-time naming a real calendar date. `Date` and `DateTime.make` read `"1"` as 2001 and roll `30 Feb` over to March, so both readers check the shape and the calendar before parsing; a breach is `S3MalformedResponse`.
- **Signing.** Every request is signed with `SigV4` at the instant `DateTime.now` reads, so `TestClock` drives it; the body's SHA-256 is the signed payload hash. Every header the client sets (`content-type`, the conditional headers, `range`, each `x-amz-meta-*`) is signed. A `CryptoError` from signing is a broken `Mac` layer and dies.
- **No trace context to the store.** The client runs every request with `HttpClient.TracerPropagationEnabled` off: the store is a third party and would otherwise receive the trace and span ids. The client span is still recorded locally.
- **Every body is drained**, on every status, before the status is read, so a connection goes back to the pool and an error document can be parsed.
- **Status dispatch.** `put`: 2xx is `S3PutResult` (an ETag header is required), 412 is `S3PreconditionFailed`, and a 409 whose `<Error>` document's `Code` is `ConditionalRequestConflict` is `S3ConditionalConflict`: AWS answers it for a conditional write that raced another write to the key and documents that the caller retries; any other 409 is `S3RequestFailed`. `get`: 200 and 206 are `S3Object`, 304 is `S3NotModified`, 404 is `S3NotFound` only when the body is an `<Error>` document whose `Code` is `NoSuchKey`, which S3, R2 and MinIO always send; any other 404 (`NoSuchBucket`, an HTML proxy page, plain text, an empty body) is `S3RequestFailed`, because a missing bucket or a misrouted endpoint must not read as a missing object. `head`: 200 is `S3ObjectHead`, 404 is `S3NotFound` (a HEAD carries no error document to tell a missing bucket apart). `delete`: 2xx, or 404 `NoSuchKey`, is success, matching S3's own idempotent delete. Everything else is `S3RequestFailed`, with the `<Error>` document's `Code`, `Message` and `RequestId` when the body is one.
- **Strict listing.** The body is decoded by core `effect/encoding/Xml`, which checks well-formedness, never expands a DOCTYPE entity and fails past a nesting or token limit.[^core-xml] A 200 whose root is `<Error>` is `S3RequestFailed`; any other root (an HTML page, an empty body, text that is not XML) is `S3MalformedResponse` naming what was expected and what was seen. Inside `ListBucketResult`: `IsTruncated` is required and is `true` or `false`; each `Contents` needs exactly one `Key`, an integer `Size` and an ISO 8601 `LastModified` naming a real calendar date (`2026-02-30` fails rather than rolling over to March); each `CommonPrefixes` needs a `Prefix`; a truncated page needs a `NextContinuationToken`; a present `KeyCount` must equal the entries plus the common prefixes read (AWS and MinIO count both) or the entries alone (a store that leaves prefixes out), so a delimiter listing never fails on a counting convention while a page that lost entries still does. Any breach is `S3MalformedResponse`, never a shorter listing. Unknown elements are ignored.
- **`listAll`** is a `Stream` that follows `NextContinuationToken` until a page is not truncated, sending `startAfter` on the first page only, and fails with `S3MalformedResponse` when a token repeats, which would otherwise loop forever.
- **No timeout or retry.** A caller bounds an operation with `Effect.timeout` and retries with `Effect.retry`; a timed-out request is interrupted and its connection released.

## Errors

Eight `Schema.TaggedError`s, each carrying `operation`, `bucket` and `key` (the prefix, for a listing), with a `message` derived from its fields. `S3NotFound`, `S3NotModified`, `S3PreconditionFailed` and `S3ConditionalConflict` (the last two with `operation` narrowed to `put`, the only operation that sends a write condition) are answers a caller branches on with `catchTag`; a first-write-wins caller retries `S3ConditionalConflict` (the condition was not decided) with a schedule that backs off, since an immediate retry is likely to meet the same conflict, and reads `S3PreconditionFailed` as "already written", since the client retries neither. `S3RequestFailed` carries `status` and, when the body was an error document, `code`, `s3Message` and `requestId` (the server's text passes through `HttpRedaction.text`). `S3MalformedResponse` carries `status`, `expected` and `received`, and the decoder's error as `cause` when there is one. `S3TransportError` carries the redacted `HttpRedaction.cause` of the client error. `S3InvalidRequest` carries a `reason` literal and the offending `field`. The per-operation unions (`S3PutError`, `S3GetError`, `S3HeadError`, `S3DeleteError`, `S3ListError`) name exactly the errors each operation can raise.

## Observability

A named `Effect.fn` span on each of `S3Client.put`, `get`, `head`, `delete` and `list`, annotated with the bucket and the key or prefix; `listAll` runs one `list` span per page. No credential, header or signature is ever annotated. No logs, no metrics.

## Testing

A scripted `HttpClient` built with core `HttpClient.make` plays the store. It re-signs every request it receives with `SigV4` from the same credentials and the request's own `x-amz-date`, and refuses one whose `authorization` differs or whose `x-amz-content-sha256` is not the body's SHA-256, so a test proves that what reached the wire is what was signed. Crypto is `Mac.layerWebCrypto` and `Digest.layerWebCrypto`. A golden corpus of `ListObjectsV2` and `<Error>` fixtures, with a provenance README, covers AWS-, R2- and MinIO-shaped pages, entity-escaped keys, an HTML page, an empty body, a wrong root, a DOCTYPE entity, an over-deep document and every strictness breach above. A structural test walks `src/` and fails on any `node:` import. The client adds no cancellation wiring of its own: core `HttpClient.make` gives each request an `AbortController` and aborts it on interruption, body read included. `__test__/interruption.test.ts` pins that over the real `FetchHttpClient` and a `fetch` that hangs on the request or mid-body.
