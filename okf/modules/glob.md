# glob

## Purpose

`@effected/glob` is glob matching as pure string→predicate compilation. Its engine is a full-fidelity vendored port of minimatch, brace-expansion and balanced-match, each ported file carrying its upstream attribution and license header — those notices are never edited, since the MIT files carry the full permission notice as license compliance. See [glob is a full-fidelity vendored port](../decisions/glob-full-fidelity-port.md) for why the whole dialect ships rather than a call-site-scoped subset.

## Tier and dependency posture

[Pure tier](../glossary/library-tier.md): `effect` is the only peer, with zero runtime dependencies, no services, no layers, and no `R` anywhere. It vendors its engine because of the kit's dependency policy — pure and boundary packages take no external runtime dependency — not because it lacks IO; under the [tier taxonomy](../glossary/library-tier.md), pure is a dependency statement, not an IO one, and glob also happens to do no IO, but that is incidental to its tier. The `minimatch` devDependency is the **test oracle only**, pinned exactly to 11.0.5, the version whose behaviour the engine follows, and imported only under `__test__/`; it must never move to `dependencies`, and it moves only after the engine has been reconciled against the new version.

The minimatch files keep minimatch 10.2.5's regexp-and-`AST` shape and take 11.0.5's behaviour: its `**` fixes; an empty path portion matching only an empty pattern portion; a `.` or `..` portion matching only through literal dots; no wildcard taking the leading dot of a dotfile without `dot`, even a class beside other magic (`[.]*`) or a `*` after an extglob that matched nothing (`*(a|b)*`); a `!(...)` negating exactly its own sub-pattern, so `!(*)` matches nothing (these three are answered by minimatch 11.0.5's own one-portion matcher, vendored from `@isaacs/nonrecursive-glob-match` 1.1.0 as `internal/matcher.ts`, for every magic portion (the regexp it still builds is compile-time validation only); every regexp it needs is built at compile, so matching stays total, and a portion with any extglob builds no regexp of its own, which removed 10's per-negation doubling and its exponential backtracking on nested quantified extglobs); only regexp syntax escaped in a portion's regexp (11's `reEscape` set), so an escaped `|` matches itself and a `,`, `#`, space or `-` beside a POSIX class compiles; an extglob opener that is never closed reading as literal text; a `[` that never closes reading as a literal, with extglobs after it still parsed; a portion that is exactly an empty extglob read with extglobs off (`*()` is a `*` and a literal `()`); a class being a literal only when its body is one character; its win32 roots (a `..` can not remove a drive letter or a UNC host and share, UNC host and share compare without case, and `//?/UNC/host/share` matches `//host/share`); its `optimizationLevel` 2 bound and dedupe; and a numeric brace range of 100 or more values (`{0..999}`) kept as one magic portion, matched by 11's matcher rather than expanded, so `hasMagic` is true for it, `GlobSet` buckets it as a wildcard, `enumerationRoots` stops at it, and no expansion budget applies to it (#1278). Before 11.0.5 the port kept 10's win32 handling, which let `C:/a/../../x` match `x`. Not taken: the removal of `maxExtglobRecursion` (still accepted, it now limits nothing) and the `normalize` option. brace-expansion's `expand_` follows 5.0.12's iterative scan, with its two bounds; `parseCommaParts` keeps 5.0.7's recursive shape.

## `**` is real

`packages/**` matches `packages/a/b`. The trailing-`/**`-to-`/*` rewrite some glob implementations carry is deliberately **not** reintroduced: it silently misses nested matches. The consumer-side cost — an enumerator must do a bounded recursive descent instead of a single-level directory read — is exactly what the `crossesSegments` metadata (below) exists to drive.

## Module layout

Three concept modules plus the vendored engine: `GlobPattern.ts` (single-pattern compilation, matching, metadata, options, and the error), `GlobSet.ts` (multi-pattern include/exclude sets) and `Wildcard.ts` (the wildcard-only matcher, which does not touch the engine). `internal/` holds the vendored engine plus `limits.ts` (the zero-dependency leaf holding every numeric cap and the raw guard signal) and `types.ts` (an engine leaf that breaks the upstream AST/index type cycle `noImportCycles` forbids). The split is a cycle firewall: the engine throws raw guard records at compile time and never imports the facade, and only the two facade modules materialize them into the typed error.

## GlobPattern

A `Schema.Class` with one encoded field, the pattern source; the compiled matcher is cached in a non-encoded private instance field, since private indexes live outside the schema and are never encoded. Every construction path — `make`, `new`, decode, `FromString` — validates **compilability under default options** via a schema check, so a `GlobPattern` value is always defaults-compilable; options refine matching but never admit a defaults-rejected pattern. `matches` is **total**: pure, with no error channel, and every compile-time guard fires before an instance exists, so nothing throws at match time.

**`Result` is the primitive.** `compileResult` holds the compilation, and `compile` is `Effect.fromResult` over it behind the named span — the span is the whole reason the `Effect` form exists, per the [sync primitive policy](../conventions/sync-primitive-policy.md). Compilation is pure, synchronous and `R = never`, so a synchronous host must not be made to build a runtime to compile a pattern.

A `FromString` transformation schema exists for embedding patterns in config schemas; its decode failures surface as `SchemaError`. `escape` and `unescape` statics support building patterns from user-supplied literals. `GlobPatternOptions` exposes minimatch's full options surface, schema-validated. **Invalid options are a developer wiring error and raise a defect** at construction; the typed channel stays reserved for malformed *patterns*. `braceExpandMax` is schema-bounded rather than a bare positive integer, because it is the one cap that can produce a compile-time typed failure — bounding it above by the stock budget guarantees permissive options can never admit a pattern the defaults check would reject; caps tighten, never raise. The error is a `Schema.TaggedError` carrying the pattern, a `reason` literal union, and structured limit/actual fields; malformed input is never a defect — a portion whose regexp the runtime rejects (one too large for its regexp engine, about 32,000 literal characters and a wildcard in one portion) fails typed as `InvalidRegExp`, with `limit` and `actual` 0, and a compile past its regexp work budget fails typed as `CompileBudgetExceeded` — and extglob over-nesting does not add a reason (it degrades to literal matching, matching upstream).

**Not a duplication of core.** `effect` ships `FileSystem.glob`, a filesystem-*scanning* glob; this package is deliberately a pure string→predicate matcher with no IO, which is exactly why the kit can point it at non-file candidates — `git ls-tree` entries, package names. Consumers wanting scan-plus-match against a real filesystem should reach for core's `FileSystem.glob` instead.

### The enumeration metadata

`enumerationPrefix` (the longest literal directory prefix) and `crossesSegments` (whether the pattern can match more than one level below that prefix — true iff it contains `**` or a `/` after the first magic segment) are API with no upstream analogue, designed for the enumerator contract; a substring-to-last-`/` prefix is wrong once `**` is real. Both are computed under the options the pattern was compiled with. Under `matchBase` an alternative that compiles to one path portion matches a path by its basename at any depth (`*.js` matches `b/d/f/g.js`, and so does `x/../*.js`, which glob pops to `*.js`), so it contributes no literal prefix and makes `crossesSegments` true (#1261). The `matchesByBasename` getter reports whether any alternative is such a row, so a walker bounding its reads by depth or by hidden names knows when no bound holds without re-deriving it from the source; `enumerationPrefix`, `enumerationRoots`, `crossesSegments` and `literalPrefix` already account for it. The rule is read off the compiled rows, never the source, so every collapse route glob takes is covered by construction.

`enumerationPrefix` is meaningful for **non-negated** patterns only: it is computed from the *inner* pattern, but a negated pattern's `matches` inverts, matching everything the inner pattern does not — and those matches can land outside the prefix. A negated pattern's walk must therefore ignore the prefix entirely and deep-walk from the root unconditionally, regardless of `crossesSegments`.

**`literalPrefix`** is the unexpanded counterpart: the literal leading segments before the first magic segment, unescaped, spelling kept, no trailing slash, `""` for the base and `/` for a root-anchored magic pattern. An unescaped `{` is magic (braces are not expanded, unless `nobrace`), an all-literal pattern yields itself, and a negated pattern yields its inner prefix, so guard on `negated` as for the others. `literalPrefix` gives `""` when an alternative matches by basename, as `enumerationPrefix` does (a slash-less `src` under `matchBase` also matches `a/src`). `literalPrefix` is spelling-only and never folds case: under `nocase`, `SRC/Lib/**` gives `SRC/Lib` although the pattern also matches `src/lib/a.ts`, so it is not a safe walk root on a case-sensitive filesystem. `enumerationPrefix` is more conservative there, since `nocase` turns a letter segment into a case-insensitive matcher and it stops at it. `enumerationPrefix` keeps its slash-terminated, brace-common form for its consumers.

**`extglobBang`** is an opt-in option (an engine adaptation in `parseNegate`) that stops negation before a `!` opening an extglob, as picomatch does, except before `(?` plus one of `!=<:` and under `noext`. It is off by default because the package matches its minimatch oracle by contract, and the compliance rows that pin a leading `!(` as negation stay as they are. It promises parity with picomatch at that one point only. `nonegate: true` already gives picomatch's answer for `!(`, but also turns off plain `!a`. `GlobSet` cannot reach the option: it has no options surface and strips one `!` itself as the exclusion marker, so `!(src)/**` in a set excludes `(src)/**`.

**`enumerationRoots`** keeps the alternatives apart where those two fold them into one answer (the shared prefix, "deep if any is"): it returns one `EnumerationRoot { prefix, deep, spellings }` per brace alternative, so `packages/{a,b}/src/*.ts` reads `packages/a/src/` and `packages/b/src/`, one level each, rather than all of `packages/`. `prefix` is canonical and slash-terminated (no `.` or empty segment, a `..` resolved against the segment before it, a leading `..` kept so a walker can still refuse the climb; `""` is the walk's own base), so `{src,./src}/*.ts` has the single root `src/`; an all-literal alternative's final segment is a file name and is excluded from the prefix. A root inside a `deep` root's prefix is dropped and its spellings join that root's, so two kept roots never yield the same file. A climbing prefix (`../x/`) is never inside the base root `""`: it stays its own root, so a walker refuses it and `{**/*.md,../x/*.ts}` yields only the `.md` files, as a standalone climb yields nothing. `spellings` lists every literal prefix the root covers as the pattern spells it, in pattern order: matching is spelling-sensitive (`./src/*.ts` does not match `src/a.ts`), so a walker tests a canonical path once per spelling and answers in the earliest one that matches. Under `matchBase` an alternative compiled to one path portion has the root `""`, `deep`, spelled `""`, which absorbs every other root inside the base. Like the other getters it reads the inner pattern and ignores negation. [walker](walker.md)'s per-root walk is its consumer.

**`dot` defaults to `false`**, as minimatch's does: `*` and `**` never match a dotfile or a dot-directory. Vitest matches its include and exclude globs with `dot: true`, so a pattern meant to agree with Vitest says so with `GlobPatternOptions.make({ dot: true })`.

The contract has held under three independent consumers unmodified — `workspaces`' enumerator, `walker`'s `descend`, and `github-actions`' cache-path search-root derivation, the last under real filesystem enumeration with round-trip and real-runner coverage. What remains open: no dedicated conformance run against a reference enumerator (`@actions/glob` or similar) has been performed, so the enumeration semantics are materially de-risked, not closed.

## Wildcard

`Wildcard` is a second, separate matcher, and **not a glob dialect**: `*` matches any run of zero or more characters other than whitespace, `?` exactly one character other than whitespace, and every other character only itself. There is no separator, so `*` crosses `/`; `[`, `{`, `!`, `\` and a leading `.` are ordinary characters, with no classes, braces, negation, escapes or dotfile rule. It exists for allow-list patterns such as okfit's actor patterns (`agent:*` against `agent:okfit/claude-code`), where both this package's dialect and core's `effect/Glob` stop `*` at `/` and read brackets and braces. `Wildcard.compile(pattern, options?)` returns a predicate, `Wildcard.matches` compiles and matches in one call, and `WildcardOptions` is a `Schema.Class` carrying `nocase`, which compares literals under Unicode simple case folding (the `iu` regex flags). Characters are code points, and whitespace is the `u`-flag `\s` set.

Compiling and matching are pure, synchronous and total. Matching is a Thompson-style simulation over the pattern's tokens, never a regular expression built from the pattern, because a backtracking `\S*a\S*a…` regex is polynomial with a large exponent in the number of stars; the simulation costs at most pattern tokens × candidate code points, and consecutive stars collapse to one token, so a pattern of 100,000 stars is one token.

## GlobSet

A `Schema.Class` over an array of pattern strings with **set** semantics: a leading `!` marks an exclusion, and a candidate matches when some include matches and no exclude does. `compileResult` is the primitive here too, with `compile` derived from it exactly as on `GlobPattern`. Structural accessors serve the enumerator: deduped non-magic includes, magic includes, excludes, and an exclusion predicate. `GlobSet` pins default options internally and takes **no options surface** — it is the drift-free contract, deliberately distinct from minimatch's whole-match `!` negation, which applies at the single-pattern level. Classification is pinned **per expanded alternative**, so a braced pattern expanding to both a literal and a wildcard contributes each alternative to its own bucket.

## Hardening

Upstream already carries substantial DoS hardening, **preserved** in the port: the 64KB pattern-length cap at every entry; brace-expansion's output budget, its recursion-to-loop rewrite, and lazy tail evaluation; the ReDoS-safe brace pre-check regex mitigating CVE-2022-3517; brace-expansion 5.0.12's bound of 4,000,000 characters on an expansion (CVE-2026-14257), which fails typed as `ExpansionBudgetExceeded` where upstream truncates, and its stop after 1,000 restarts of the quadratic `{a},b}` rewrite, past which the rest stays literal exactly as upstream leaves it (one count shared by every group of a left-to-right scan, as 5.0.12's single scan loop holds it; a comma part or `{{...}}` body is a fresh scan); and minimatch 11.0.5's `optimizationLevel` 2 bound on the `**/..` split (GHSA-g3hv-75wg-m249), `braceExpandMax` rows or 1,000,000 added path portions, failing typed where upstream throws a `RangeError`, with a keyed dedupe in place of the pairwise compare that made it quadratic. Two upstream guards are kept as **authorities**, not tightened: extglob recursion (over-nesting degrades to literal and does not error) and globstar recursion (exceeding it is upstream's deliberate false-negative "correctness for security" trade) — both are invariants, so `matches` stays total. `**` matching remembers the places a walk has tried, so sections that all fail cost polynomial time rather than exponential, with or without `partial`.

`maxGlobstarRecursion` is the one recursion cap a caller can raise, and the body-section walk recurses once per `**` section, so the cap is a stack depth. It is schema-bounded at 1,000. Measured on Node 26's default stack, the walk first overflowed at about 3,250 sections with nothing else on the stack, at about 2,100 with 5,000 frames of the caller's own recursion beneath it, and at about 1,600 under `--stack-size=500`, half the default; a walk at the ceiling uses under a third of the default stack and about 62% of the halved one, so it leaves a margin in each case. Because stack depth varies by runtime and by the caller's own stack, `GlobPattern.matches` also catches a `RangeError` from the engine, and only that, answering as though no alternative matched: `false`, or `true` for a negated pattern. For a brace pattern with several alternatives that can differ from the cap's answer, since the cap fails only the alternative it cuts short and the engine tries the rest. `GlobSet` matches through `GlobPattern.matches` and inherits the answer.

Matching stays polynomial, and the package does not bound total matching work: a literal segment between two globstars against 50,000 portions takes seconds, and a brace-multiplied pattern against a 14 KB path tens of seconds. Matching is synchronous and blocks the calling thread, so an in-process `Effect.timeout` cannot cut a slow match short. A caller with untrusted patterns or paths bounds the input before matching (pattern length and source, candidate length or portion count) and lowers `braceExpandMax`, which turns the brace case into a compile-time `ExpansionBudgetExceeded`; a deadline, where one is needed, is enforced off-thread, by a worker that is terminated, a subprocess, or the host's own deadline. See [the hostile-pattern decision](../decisions/glob-hostile-pattern-bound.md).

New depth guards at the shared nesting cap cover the remaining AST and brace-expansion recursion. `balancedMatch.ts` is fully iterative — no stack surface, no guard, and none should be added. One upstream hole is closed: coalescible nested extglobs recurse with a zero depth increment in stock minimatch, so it stack-overflows at default options on a roughly 60KB adoption chain that sits under its own length cap; the vendored AST parser adds a structural depth backstop counting every descent and failing typed, guarding that surface independently of the extglob recursion option. Cap defaults live in `internal/limits.ts`. Three caps are caller-settable options (`braceExpandMax` and `maxGlobstarRecursion` bounded above, `maxExtglobRecursion` not, since its over-nesting degrades to literal under the parser's structural depth backstop), validated by the options schema so an invalid value is rejected as a wiring defect before any guard sees it; the internal-only caps follow the [walker](walker.md) `maxDepth` rule — a NaN or non-integer reaching a guard can only come from code, is programmer error, and dies as a defect. Malformed input at every surface exits through the typed error, never a defect, never a hang.

## Observability

Named `Effect.fn` spans on the public fallible boundaries only — the two `compile` statics; the span is the *entire* content of those wrappers, the engine having moved down to the `*Result` primitives. `matches` is infallible and hot, so it is span-free. No metrics; telemetry-agnostic.

## Testing

`@effect/vitest`, `it.effect`, `assert.*` — never `expect`; tests in `__test__/`. No platform packages, no mock layers (no `R`), no `TestClock`. The engine is tested below the facade as well as through the public surface, in three families: a compliance fixture table asserting expected result *and* oracle agreement on every row; oracle property tests generating over the full dialect against the real `minimatch` package, asserting the vendored engine agrees modulo the documented deviations (if the engine disagrees with the oracle, fix the engine, never the expectation); and a hostility suite — oversized patterns, expansion bombs, deep brace nesting, extglob adoption chains, long globstar chains, deep comma-part chains — each failing through the typed error with the right reason, never a stack overflow, OOM or hang, plus the NaN and non-integer cap defect guards. Beside them, `match-limits.test.ts` pins the `maxGlobstarRecursion` ceiling, a stack sweep proving `matches` answers rather than throws when the engine overflows, and a lowered `braceExpandMax` failing the hostile brace case at compile; `Wildcard.test.ts` covers the wildcard matcher, with a mutation control on whitespace stopping `*`.

The oracle is minimatch 11.0.5. Beside typed failures (where the kit rejects a pattern 11 accepts, never a different answer), it has one standing exception, an 11.0.5 defect: 11 joins a pattern's brace alternatives with `|` into one matcher, so a `[` in one alternative and a `]` in another become a class (`b**{Z..a}` does not match its own text), and the engine answers the union of the alternatives; `compliance.test.ts` names it `bracketsAcrossAlternatives`. A numeric range of 100 or more values is no longer an exception: the engine keeps it one portion as 11 does, and `compliance.test.ts` pins it against the oracle. `GlobSet` classifies with `braceAlternatives`, which writes each alternative back as text: a kept range as `{lo..hi}`, and every brace that expansion unescaped escaped again, so `\{a,b}` stays the literal `{a,b}` and is never expanded twice. An include whose range follows a `$` or a literal backslash, or whose alternative does not compile alone, stays one wildcard, the whole pattern; `GlobSet.compileResult` and the schema check classify eagerly, so no guard trips in `matches`. One more typed refusal is the kit's: a compile's work is budgeted (`MAX_REGEXP_WORK`, 8,000,000 units, a regexp's length plus 2,048 per Unicode property escape, plus 4 per matcher graph item, so a kept range copied into every brace alternative is charged per copy; a `GlobSet` is one compile, its members sharing one budget and handing their engines to their patterns: each POSIX class costs about 4,096 units in its validation regexp, so a set in which every member has one tops out at roughly 1,900 members, failing typed past it, while sets of plain, brace and range lines compile at 20,000 lines), so `[[:alpha:]]{0..99}{0..99}{0..9}`, which ran the process out of memory, fails typed as `CompileBudgetExceeded`, where minimatch 11, building its matchers lazily, compiles it in 275 ms. `__test__/globstar.test.ts` keeps the multi-`**` and `partial` rows that minimatch 10.x answered wrongly as regressions, checked against the oracle and a reference matcher.

## Consumer contract

Glob itself does **no** enumeration — pure string→predicate only, and that is a load-bearing boundary. `workspaces` consumes it at three points: dependency matching expressed over `GlobPattern` (so `workspaces` carries no `minimatch` runtime dependency), the `packages:` enumerator expressed over `GlobSet` (a literals fast path, wildcards driving directory reads from `enumerationPrefix`, and `crossesSegments` triggering the bounded descent that makes `**` real end to end), and at-ref discovery matching the same compiled set against `git ls-tree` entries. `walker` is the second consumer and the first outside `workspaces`: its `descend` uses glob type-and-property only — a type-level import, the metadata getters, and `matches` — so the boundary holds in the other direction too, since the walker that does the IO takes no value dependency on the matcher that does none. `walker`'s `compileAndExpand` does value-import `compileResult` and the error to own the compile-plus-expand seam, and `compileResult` being the primitive is what makes that seam cheap: `walker` folds a `Result` in place instead of crossing an `Effect` boundary twice to reach the same engine.
