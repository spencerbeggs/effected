# Gotcha

* ["Wait for the kit" leaves raw spawns and duplicated regex behind](action-missing-kit-surface-residue.md) - An action written before a kit surface existed keeps its workaround even after the kit ships the real thing, because nothing forces a re-audit — raw git spawns and a hand-copied closes-keyword regex both outlived the packages that made them unnecessary.
* [A CLAUDE.md that reads confidently can be citing a tree that no longer exists](action-fossilized-context-files.md) - An action repository's context files kept naming deleted workflows, renamed config files, absent directories and superseded tools long after the repository itself had moved on — nothing about reading the file signals that its claims are stale.
* [A PR's check runs post to the merge ref, not the head SHA](pr-checks-post-to-merge-ref.md) - Querying GitHub check runs or conclusions scoped to a pull request's head SHA can report no failures even when a required gate actually failed, because the check posted against the merge ref instead.
* [A branch build's dist/ carries the previous release's version](branch-build-reports-previous-version.md) - An unreleased branch's dist/** manifest reports the last published version number, identical to what the registry is already serving — a consumer linked against that build must take its pin from the release, never from the linked artifact's own version field.
* [A capability recon pass at package level misses constructs the kit already ships](action-capability-discoverable-only-by-name.md) - Checking "does the kit have a package for X" instead of "does the kit have this exact construct" declares real capabilities absent when they already exist under a different or unexpected name.
* [A clean issue tracker on a scaffold is not evidence it works](action-zero-open-issues-not-readiness.md) - A template repository with zero open issues advertised a dead predecessor API, shipped empty entry files, and had no tests — the absence of open issues measured nobody looking, not nothing being wrong.
* [A degraded build-time decode failure reports a truthful-sounding empty result](action-bundle-time-silent-empty.md) - Folding a build-time data decode failure into an empty array with orElseSucceed produces a result that looks like "no versions found" instead of "the bundle is broken", and nothing about the shape of the output tells them apart.
* [A flaky jsonl watcher is probably a dropped null-filename event, not an unreliable platform watch](jsonl-watcher-flake-filename-drop.md) - The instinct to blame the platform file watch as generically unreliable leads to an unjustified polling timer; the known, reproducible cause is a directory-watch event drop under load.
* [A green typecheck after linking an unreleased kit build hides a second effect instance](link-override-passes-typecheck-with-two-effects.md) - Linking a consumer straight at a kit package's directory typechecks cleanly once every clashing sibling is linked too — that clean state is the trap, because it is produced by two resolved effect instances in one process, not by one.
* [A language-less Code node stringifies as an indented block, not a fenced one](languageless-code-node-indents.md) - A Code node with neither lang nor fenceChar set serializes through Markdown.stringify as an indented code block by default, which most readers do not expect from a node they think of as "a fenced code block with no language".
* [A macOS Actions runner's npm cache is partly root-owned](action-macos-npm-cache.md) - GitHub's macOS runners ship a partly root-owned ~/.npm/_cacache, so a bare npm pack or npm publish dies with EACCES unless the cache directory is redirected explicitly at the call site.
* [A missing PublishabilityDetector fails far from where it was wired](publishability-detector-diagnoses-late.md) - Workspaces composites neither provide nor require a PublishabilityDetector, so a missing one surfaces as an unclosed R at whatever downstream operation asks the publishability question, not at the layer-composition call site — and Layer.provide silently discards a detector instead of wiring it.
* [A new stringify option added to one adapter silently no-ops on the other two](yaml-three-stringify-adapters.md) - @effected/yaml has three hand-copied option adapters into the engine's stringify input; adding a field to one and forgetting the others compiles clean and drops the option at runtime.
* [A plain pnpm install can silently strip platform binaries from the lockfile](plain-install-strips-platform-binaries.md) - An ordinary pnpm install has previously removed turbo, biome, and tsgo's platform-specific optional-dependency entries from pnpm-lock.yaml with no error.
* [A plausible schema.org property on the wrong type serializes cleanly and gets silently ignored](schema-org-property-not-on-type-silently-ignored.md) - A property that exists in the schema.org vocabulary but is not legal on the node's @type passes through JsonLdDocument's serializer untouched, and only Conformance.check catches it.
* [A renamed field typed never turns a silent conditional-spread drop into a compile error](npm-renamed-field-silent-spread-drop.md) - Dropping a renamed field outright lets a caller's conditional spread (`...(token !== null ? { token } : {})`) compile clean while silently omitting the field, because a spread of an unknown property is not an excess-property error — typing the deprecated field never makes the same spread fail to compile instead.
* [A scope-qualified filter, a version-only sort, and a plain Redacted all fail silently](action-silent-scope-and-encoding-failures.md) - Three call sites that look like they return an ordinary empty or degraded result actually mean "this call was answered wrong" — a bare ref against a fork PR, a semver-only tag comparison, and Schema.Redacted's default encoded literal.
* [A subpath entrypoint named after its own concept module fails at two layers](subpath-case-collision.md) - Naming a subpath export key the same as one of its concept modules, differing only in case, first breaks tsc outright and then, once renamed, resurfaces as a misleading CI-fatal API Extractor error.
* [A turbo cache hit reads exactly like a fresh build in the log](turbo-cache-hit-replays-clean-log.md) - FULL TURBO and a clean issues.json summary print identically whether the build ran or a stale cached artifact was replayed; only `dist/<target>/issues.json`'s generatedAt distinguishes them.
* [A validation failure on an absent input silently resolves to the default](action-input-default-swallows-validation-failure.md) - Config.withDefault built over a missing-data classification swallows a validation error the same way it swallows a genuinely absent input — dry-run: yes silently becomes false.
* [An `as never` cast and a second process.env read both compile clean and fail at runtime](action-r-channel-erasure-and-env-shadowing.md) - Casting an unclosed R channel to never, and reading process.env outside ActionEnvironment, both typecheck and pass review — the failure surfaces only at run time, and only when the omitted layer or the shadowed variable actually matters.
* [An unprotected environment runs fork code with secrets](unprotected-environment-runs-fork-code-with-secrets.md) - A fork PR's Fork Approval job can start immediately without a Review deployments prompt and then fail with "has no required-reviewers rule" — GitHub auto-creates an environment with no protection rules the first time any workflow references its name, so the dispatcher verifies required_reviewers itself before handing fork code the App token and Claude OAuth token.
* [Calling Store.layerSqlite inline at two provide sites opens the database twice](store-layersqlite-opens-twice.md) - Store.layerSqlite is a parameterized factory, and Effect layers memoize by reference — calling it a second time with identical options builds a second layer instance, opening a second connection to the same database file.
* [Converting doubles and the test runner together rewrites the gate alongside what it gates](action-testing-migration-ordering.md) - A passing test suite during a migration is the characterization gate proving behavior did not change — swapping the runner in the same step changes what "passing" means, so a still-green suite no longer proves anything.
* [Explicit markdownlint-cli2 path arguments do not narrow the scan](markdownlint-cli2-merges-path-args.md) - Passing a specific file to markdownlint-cli2 merges it with the config's repo-wide globs instead of narrowing the scan, so "lint just my file" lints the whole repository.
* [ReleaseTag defaults to strict SemVer with no version prefix](releasetag-strict-semver-default.md) - A repository whose git tag history uses a v-prefixed convention gets bare-SemVer tags from ReleaseTag by default, silently diverging from its own existing history unless versionPrefix is passed explicitly.
* [Resetting a branch to its pull request's base closes that pull request](branch-reset-closes-pull-request.md) - GitBranch.upsert's reset path makes a branch's head equal its pull request's base, and GitHub auto-closes any pull request whose diff goes empty as a result — even when a follow-up commit was already planned to re-add content.
* [Run.text trims output that depends on fixed columns](run-text-trims-fixed-columns.md) - Run.text trims the whole captured result, which silently corrupts a command's output whenever its meaning depends on a leading column of whitespace, such as git status --porcelain.
* [Running the bundler script directly fakes a clean build gate](direct-prod-build-fakes-a-clean-gate.md) - node savvy.build.ts --target prod skips build:dev, emits no .d.ts, and leaves a truncated issues.json shaped exactly like a passing gate.
* [SectionId keys render into markers exactly as constructed, with no normalization](sectionid-renders-verbatim.md) - SectionId keys are stored, rendered and compared verbatim and case-sensitively — a consumer expecting the renderer to normalize case gets silent duplication instead of a match, because canonicalization never happens and must be done at construction.
* [The Catalog Sync check goes RED when it found and fixed drift](catalog-sync-check-goes-red-when-it-repairs.md) - A red "Catalog Sync" check run on a PR to main usually means the automation found drift, repaired it, and committed the fix — not that anything is broken. The job also checks out and commits to main itself, so a feature branch's own PR never shows the catalog diff.
* [The required Claude Code Review check fails on an empty-body approval](claude-code-review-empty-approval-fails.md) - This repository's REQUIRED "Claude Code Review" check reports failure with "Review produced no comment" whenever the reviewer approves a pull request with an empty review body, deterministically and on every release PR too.
* [The root tsconfig's skipLibCheck override exists only to work around one vitest .d.ts](vitest-broken-dts-needs-skiplibcheck.md) - The root tsconfig.json sets skipLibCheck true against the silk preset's own default of false, solely because vitest@5.0.0 ships a declaration file that fails to typecheck on its own.
* [Vendored repos are empty on a fresh clone](vendored-repos-empty-on-fresh-clone.md) - A fresh clone, CI runner or new git worktree starts with an empty .repos/ checkout, even though .gitmodules and .repos/config.json name every vendored repo.
* [Writing frontmatter re-serializes the whole block and can drop untracked data](markdown-frontmatter-write-loses-untracked-data.md) - A frontmatter write looks like a targeted update but actually re-serializes the entire block from the decoded value, silently dropping anything the codec's data model does not carry — such as yaml comments.
* [ae-forgotten-export on _base looks like a real export bug; it is a synthesized, un-nameable symbol](api-extractor-forgotten-export-on-class-factories.md) - API Extractor reports ae-forgotten-export on the anonymous heritage base an Effect class factory synthesizes; the fix is a narrow, logged suppression, never a hand-written base export.
* [catalog:build is missing from pnpm-workspace.yaml because it is injected](catalog-build-absent-from-workspace-yaml.md) - Grepping pnpm-workspace.yaml for catalog:build finds nothing, which reads as a broken or unconfigured catalog reference rather than the configDependency-injected catalog it actually is.
* [lint-staged normalizes every committed shell script back to 644](lint-staged-strips-exec-bit.md) - A shell script's executable bit flipping from 755 to 644 in a commit diff is the lint-staged shell-script handler working as designed, not mode drift or accidental damage.
* [npm run silently claims flags meant for the script](npm-run-eats-flags.md) - `npm run <script> --flag` delivers nothing to the script itself — npm claims the flag for its own argument parsing — while pnpm, yarn and bun all forward post-script arguments without any extra syntax.
* [pnpm add --config silently strips integrity hashes from every config dependency](pnpm-add-config-strips-integrity-hashes.md) - Adding one new config dependency with pnpm add --config can remove the +sha512 integrity suffix from every existing configDependencies entry, not just the one being added.
