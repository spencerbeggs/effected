# @effected/cli

The `effected` command. `src/commands/root.ts` is the command tree (`makeRootCommand(deps)`); `src/main.ts` assembles it on `CliRuntime.main` (`run(options, deps, platform)` so tests drive it in-process, `main` runs it on the Node services and is the one place `cwd` is read); `src/bin.ts` calls `main()` with no distribution; `src/version.ts` holds `CLI_VERSION`, which the bundler replaces at build.

- The `effected` bin name is shared with a carrier package, which passes its own `distribution` to `main`.
- `--version` prints `effected <version>` through `env.formatter`; the "via" suffix comes from `CliRuntime.main`'s `distribution` option, never from the formatter.
- Shared logic belongs in `@effected/engine`, not here. Tests live in `__test__/` and run in-process over `@effected/memfs`, except the e2e that spawns the built bin.
- `src/commands/schema/` is `effected schema build|check|validate` over `@effected/engine/schema`. The engine answers verdicts as data; `execute.ts` owns what a front end owns: the `--force` and version-mismatch warnings, `StepSummary.append` (never the engine, so `schema_check` over MCP does not write it), and every exit code, kept as `okf/interfaces/schema-commands.md` lists them, with `VersionMismatchError` at 2. Load that Interface before changing a flag, an exit code or the report.
- **`LiveProgress.ts` is the only module here that imports Ink, React or `@effected/cli-kit/ui`, and `execute.ts` reaches it by dynamic import**, only for human output on an interactive run. A static import of it costs React on every run: `__test__/e2e/schema-no-ink.e2e.test.ts` runs the built bin under a preload recording every resolved module and fails on it. `vi.mock("ink")` cannot prove this, because vitest externalizes the built `@effected/cli-kit`.
- `src/commands/package/` is `effected package build` over `@effected/engine/build`. The CLI has no dependency on `@effected/bundler`, and `execute.ts` imports the engine's build entry dynamically: it loads the bundler and its toolchain, about 340 ms that `--version` and `effected schema` must not pay. `__test__/e2e/package-build.e2e.test.ts` holds that with a module recorder. `main` reads `CI` and `GITHUB_ACTIONS` into `deps.ci`. Exit `2` carries the engine's message in the CLI's own `PackageConfigError`, so no bundler type reaches this package's public types. Under CI the annotations follow the document on stdout; with `--format json` they go to stderr so stdout stays one document. `@effected/jsonl` is a devDependency, only for a test's `JournalWatcher` double.
- `validate` never draws: its `Started` names the config's schemas, none of which is what is being validated.
- `typescript` is peered as the literal `>=7.1.0-beta <8`, not `catalog:build:peers`, because that catalog value pins a prerelease exactly; the plugin's `entry.test.ts` holds the four manifests to the same string.
