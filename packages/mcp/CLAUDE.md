# @effected/mcp

The `effected-mcp` server. `src/tools/identity.ts` and `src/tools/schema.ts` are the tools; `src/server.ts` assembles `ServerLayer(options)` on `McpStdio.layer`; `src/main.ts` runs it under `McpGuard.run` with a lazy `load` (no static runtime imports, `exitBeforeConnect` for both events), and provides the Node platform; `src/bin.ts` calls `main()` with no distribution; `src/version.ts` holds `MCP_VERSION`, which the bundler replaces at build.

- The `effected-mcp` bin name is shared with a carrier package, which passes its own `distribution` to `main`.
- Stdout is the JSON-RPC wire: nothing in this package writes to it. A schemastore config can, because it runs in this process, so `main` confines each schema tool call with `StdioCapture`, stdout to stderr.
- `schema_check`, `schema_build` and `schema_validate` answer drift, staleness and a failed validation as results. `ToolRefusal` is for a config that cannot be found or loaded, a path outside the root, or a run that could not finish. A refusal after a warned version mismatch repeats the warning, because the engine's errors do not carry it.
- Handlers capture `FileSystem` and `Path` in `toLayer`'s effect form and declare no `dependencies`.
- Containment: the root is the nearest `pnpm-workspace.yaml`, otherwise `.git`, otherwise `cwd`, found once when the handlers build. `config`, `payload`, `schema` and a payload's own `$schema` are held to it through `PathContainment.isWithin`; every reference is checked, because the engine resolves any reference as a path before it tries it as an identity, so `https:/../../x` is a path. Relative parameters resolve against the root; discovery with no `config` starts at `cwd` and stops at the root, because a config is code and one above the checkout may be someone else's. A stray `pnpm-workspace.yaml` above a `.git` widens the root, and with it the discovery ceiling. A config's own output paths are not held to it.
- `schema_build` and `schema_check` load the config outside one `Exclusive` lane and walk inside it. Each document is replaced atomically, but a build writes several files, so a reader between two writes would answer from a mix of old and new. A lane timeout would abandon the engine's `Effect.tryPromise` import, so the load must stay outside. `schema_validate` takes no lane: it reads one document, which is the old text or the new.
- Shared logic belongs in `@effected/engine`, not here. Tests live in `__test__/` and drive the server in-process through `McpHarness` from `@effected/mcp-kit/testing`.
