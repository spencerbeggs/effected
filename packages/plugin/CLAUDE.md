# @effected/plugin

The effected carrier: no logic of its own. `src/index.ts` re-exports `defineSchemastore`, which is `@effected/schemastore`'s `defineConfig`. `src/bin/effected.ts` and `src/bin/effected-mcp.ts` each call their front end's `main` (`@effected/cli/main`, `@effected/mcp/main`) with `distribution: { name: "@effected/plugin", version: PLUGIN_VERSION }`; `src/version.ts` holds `PLUGIN_VERSION`, which the bundler replaces at build.

- The front ends declare the same bin names on purpose (each also installs alone), so the e2e passes `allowSharedBins` and proves the carrier's shims with `runCarrierBin` / `carrierCommand`.
- `__test__/e2e/packed-install.e2e.test.ts` packs `dist/prod/npm/pkg` for the whole closure: build it first with `pnpm build --filter @effected/plugin...`. It skips locally without that build and fails under CI. Its pnpm workspace case proves the `publicHoistPattern` that `@effected/pnpm-plugin-effected` sets.
- `__test__/entry.test.ts` holds what the e2e cannot see cheaply. **The root stays cheap**, because a config file imports it: it reaches no front end, no `@effected/engine`, no `@effected/bundler`, no `tsdown`, no `ajv`, no `jiti` and no Ink, proven by running the built entry under a module recorder. A static import from a bin shim's graph into `src/index.ts` costs every config that.
- **The chain is pinned with `workspace:*`, publishing as exact versions**: this package to `@effected/cli`, `@effected/mcp` and `@effected/schemastore`; `cli` and `mcp` to `@effected/engine`; `engine` to `@effected/schemastore` and `@effected/bundler`; `bundler` to `@effected/changesets`; `schemastore` to `@effected/semver`. A patch floating in below would change the tool's output with no plugin bump, so bumping `schemastore` ripples down the chain. `entry.test.ts` reads the six manifests. Never loosen a link to `workspace:^`.
- The schema cases in the e2e copy `__test__/e2e/fixtures/schema-consumer` into each installed consumer and compare what `effected schema build` writes with its `expected/`, byte for byte. An `effect` advance that changes the output changes that copy: read the difference first, then run `pnpm exec effected schema build` from the fixture's directory, whose `outputDir` is `expected`. The mismatch case makes its second `@effected/schemastore` by rewriting the real tarball's version and stamp, because a stale copy has nothing to install from.
- **`public/tsconfig/{ecma,root}.json` are the presets a consumer's tsconfig extends**, as `@effected/plugin/tsconfig/*`. They live under `public/` because the build copies only that directory into the package, and the export's `./public/` prefix is stripped from the emitted manifest. A bare `tsconfig/` directory would keep the export and ship no files. `__test__/tsconfig-presets.test.ts` follows a consumer's `extends` through the built package with the compiler.
- **`typescript` and `@types/node` are peers here and on `@effected/cli` and `@effected/mcp`,** so a consumer's install surfaces the bundler's peer. It is not only a courtesy: `@effected/bundler` peers a prerelease `typescript` that `tsdown`'s optional peer range does not admit, and with no peer at the installed package npm's resolver spins at full CPU and never finishes. The packed-install e2e's `@effected/mcp` alone case times out without it.
- `typescript` is peered as the literal `7.1.0-beta || 7.1.0-rc || >=7.1.0 <8`, not `catalog:build:peers`, because that catalog value pins a prerelease exactly and a plain lower bound would admit `-dev` nightlies; the plugin's `entry.test.ts` holds the four manifests to the same string.
- Nothing belongs here but bin shims and that re-export. Shared logic goes in `@effected/engine`.
