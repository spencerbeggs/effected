# @effected/shell

A tolerant shell-syntax lexer and segmenter: `ShellSyntax.parse(input)` returns a `ShellScript` of segments (simple commands split on `&&`, `||`, `;`, `|`, `|&`, `&`, the `case` terminators and newlines), each with its words, leading assignments and redirections, and words carrying their quoting provenance as typed parts. `ShellCommand.fromSegment` resolves a segment to its command name, unwrapping `sudo`, `env`, `command`, `exec`, `nohup` and `time`. `ShellScript.allCommands({ maxDepth })` parses every substitution body to the cap and records what lies past it as a `ShellTruncation`. Built for agent-hook guards that must know every command a Bash tool call would run.

**Tier: pure.** `effect` is the only peer; no runtime dependency, no `node:` import, no service, no layer, `"sideEffects": false`. Never add a dependency: positions stay UTF-16 offsets, and a consumer that wants line/character uses `@effected/source` itself. `__test__/entrypoints.test.ts` pins the import set, the manifest and the export list.

**Design doc:** `@./okf/modules/shell.md`. Why a package, why not core `CommandLine`, and the contract: `@./okf/decisions/shell-syntax-package.md`. Load when: changing the contract, the part kinds, the operator set, the wrapper list or the grammar's reach.

## The contract (load-bearing, never weaken)

- **Never evaluate.** No expansion of any kind and no execution. An expansion is a marked part (`variable`, `commandSubstitution`, `arithmetic`, `processSubstitution`, `glob`, `brace`, `tilde`) with its span; bodies are opaque text.
- **Never fail.** `ShellSyntax.parse` is total and synchronous; it returns a plain `ShellScript`, not a `Result`. Input the lexer cannot finish becomes an `opaque` part to the end of the input plus a `ShellDiagnostic`. No code path may throw on any input; the property test in `__test__/hostile.test.ts` holds it.
- **Fail closed.** `ShellWord.literal` is `Some` only for bare, single-quoted, ANSI-C and expansion-free double-quoted parts. Adding a part kind means deciding whether it can be literal; the default is no. Where grammar is missing, over-split (report a command the shell might not run), never under-split. In particular never read a heredoc that may not be there: a spurious one hides the lines after it, a missed one only reports its body. A token whose meaning depends on an enclosing construct needs a test inside each construct, in both scanners, and the constructs come from the bash grammar, not from memory. For `<<` (a heredoc in command text, a shift in arithmetic) they are `(( ))`, `$(( ))`, `$[ ]` and the `[ ]` subscript of a command-position `NAME[` word; `let`'s operands are ordinary words, where `<<` is a heredoc. An argument `NAME=(`, `NAME+=(` or `NAME[…]=(` is a compound assignment only after a bare `declare`/`typeset`/`local`/`export`/`readonly`/`alias`/`eval`/`let` command word with no redirection since (`RawSegment.compoundAssignment`, bash's `PST_ASSIGNOK`); anywhere else bash rejects the `(` and the lexer splits it off as a subshell. bash reads on after an array's `)` into the same token, so `x=(a)#` holds no comment. Command position is bash's `reserved_word_acceptable`, not a local notion: the lexer's `Follows` states carry `time -p`, `time --`, `function NAME`, `coproc NAME`, `[[ … ]]`, `((…))` and `for NAME`. `\⏎` is gone before bash tokenizes, except in a comment, single quotes, after an escaping backslash or in a quoted heredoc body: every lookahead that joins two characters goes through `skipContinuations`, in both scanners and in `heredoc.ts`. A heredoc delimiter holding an expansion opener reads no body (`ExpansionInHeredocDelimiter`), since bash rebuilds `$( … )` from its parse. Any `$` or backtick that reaches `${…}`, arithmetic or a subscript (array keys included) quoted or escaped records `QuotedSubstitutionInExpansion`, whatever follows it: in a `'…'` run, in a `$'…'` run after decoding (`ansiCRunHoldsOpener`), as a literal `$` in a `"…"` run directly inside the frame (`"$"`, `"a$"`, not the `$` of `"$HOME"`), or after a backslash (`\$`, `` \` ``, in the frame or in such a `"…"` run). So does a bare `$` in the frame whose next character, through `\⏎`, is a backslash before `(` or a backtick: removing it leaves `$(` (`x=([$\(cmd\)]=1)` runs `cmd`; `$\n`, `$\{` and a top-level `echo $\(cmd\)` run nothing and record nothing). `$$` and the other special parameters in a `"…"` run are expansions, not literal `$`s (`"$$$"` is `$$` and then a literal `$`). bash honours the quoting to find the closer, then removes it and reads the text again in a double-quoted or heredoc `${…}`, in arithmetic and in an indexed array's key, so the `$` joins whatever follows it, the next run included: `echo "${x:-'$(cmd)'}"`, `"${x:-"$"(cmd)}"`, `"${x:-$'\x24'(cmd)}"`, `x=(['$'(cmd)]=1)` and `x=([\$\(cmd\)]=1)` each run `cmd`. Reported in every such frame, quoted or not, rather than placed as a substitution, since the operator and quoting that keep it literal, and what the `$` joins, are not modelled; a quoted `$` there is rare in real commands, and an over-report beats a hide. A top-level word is not read again, so `$'\x24(cmd)'`, `"$""(cmd)"` and `\$'(cmd)'` stay the literal `$(cmd)` with no diagnostic. Honouring the quote to find the closer is bash's default mode only: POSIX mode (`set -o posix`, `POSIXLY_CORRECT`) takes a `'` in a double-quoted `${…}` for a plain character, so `echo "${x:-'}"; cmd; echo "'}"` runs `cmd`. `nested.ts` tracks per frame whether it sits in double quotes (a `"` frame sets it, command text clears it, expansion frames inherit it, the root's comes from the lexer's `inDoubleQuotes`), and a run there that the POSIX reading leaves unbalanced (`posixReadingDiffers`: a stray `}`/`]`, or an open `"`/`${`/`$[`) records `QuotedCloserInExpansion`.
- **Every substitution is reachable.** Any part that can hold a `$(…)`, backtick or `<(…)` carries `substitutions` (or `expansions`), and `ShellScript.substitutions()` names every part kind in an exhaustive switch. A new part kind that can hold one must join that switch. `ShellScript.allCommands` walks those bodies to `maxDepth` (default `ShellScript.defaultMaxDepth`, 16) and records each substitution past the cap as a `ShellTruncation` (reason `"depth"`), never dropping one: a guard refuses a walk whose `truncated` is `true`. `substitutions()` can list a substitution beside the substitutions inside it (a `$((a) …)` falling back to a command substitution in arithmetic, a subscript, `${…}` or `$[…]`), so the walk never trusts the listing for its cost: it parses each distinct substitution once, keyed by its span in its frame (breadth first, so the first sighting is the shallowest), and enforces a budget of `maxDepth` × the input in body characters, capped at `walkCharacterLimit` (64 MiB) and `walkRecordLimit` (10,000 scripts and truncations together) scripts, recording the body that would pass it as a `"budget"` truncation and stopping. Never dedupe overlapping parts to the outermost: an inner part can be one the outer body's parse never yields. The cost model and the measurements behind the default are a decision in `okf/modules/shell.md`; never change the default without re-measuring real nesting and hostile cost, never derive the bound instead of enforcing it, and never make the walk drop a substitution.
- **Not `CommandLine.Word`.** The result types must never become core's execution vocabulary.

## Known limits

This was checked against GNU bash 5.3 only, with the reviewed shapes, every position of a backslash-newline in them, and a random differential fuzz. That is evidence, not proof: dash and zsh were not tested, and POSIX-mode bash only for the quote rule above. A guard must not treat `commands()` as a complete gate until these are closed. Three parser modes hide a command with no diagnostic: under `shopt -s extglob` (or an inherited `BASHOPTS`), `echo @(<<E)` and `cat <<E@(x)` read a heredoc bash does not; under `shopt -s expand_aliases` an alias body is never read (`alias c='git commit'`, then `c`); and POSIX mode is otherwise unchecked, except that it expands aliases in a non-interactive shell (`BASH_ALIASES[1]=cmd`, then `1` on the next line). So refuse `shopt`, `alias`, `set -o posix` and any write to `POSIXLY_CORRECT`, assignment tokens or not (`: ${POSIXLY_CORRECT:=1}`, `for POSIXLY_CORRECT in 1`, `select POSIXLY_CORRECT in 1`, `declare {POSIXLY_CORRECT,y}=1` each turned it on), and control the environment (an inherited `POSIXLY_CORRECT`, `BASHOPTS`, `SHELLOPTS` or `PS4`). `hash -p /path/cmd ls`, `enable -n printf` and a write to `BASH_CMDS` or `BASH_ALIASES` with any key, letter-free ones included (`BASH_CMDS[1]=/path/cmd; 1`, `BASH_CMDS=([1]=…)`), make a name run something else, the `alias` class: refuse them too (the README guard refuses any mention of `PS4`, `POSIXLY_CORRECT`, `BASH_CMDS` or `BASH_ALIASES` once quotes and backslashes are removed). A guard matches `ShellWord.joined` / `ShellAssignment.joined`, never `raw`: the parse joins `\⏎` (`[\⏎[` is `[[`) but `raw` keeps it, so `[\⏎[ x -eq 0 ]]`, `(\⏎( x ))` and `$\⏎{!x}` slip past a pattern over `raw`. `joined` keeps a `\⏎` only inside a top-level single-quoted or ANSI-C part, as bash does, and removes every one inside a nested part (over-joining quoted text there). Text handed to another parser is not read: `eval`, `bash -c`, `source`, `xargs`, `find -exec` and `ssh` are reported as their own name, and so are argv wrappers `ShellCommand` does not unwrap (`nice`, `timeout`, `stdbuf`, `setsid`, `doas`, `chroot`, `builtin`). Nor is text bash evaluates as arithmetic, a name or a prompt, where a quoted `'a[$(cmd)]'`, or a variable holding one, runs `cmd` (each checked under bash 5.3): `let`, `trap`, `read`, `declare -i` / `typeset -i` / `local -i` / `export -i` / `readonly -i`, a nameref (`declare -n`) and later assignments to an integer variable, a subscripted name given to `declare` / `typeset` / `local` with any options (`declare 'a[$(cmd)]=1'`, or a name a variable supplies, `declare "$x"`; `export` and `readonly` run nothing for it), `printf -v`, `[ -v` and `test -v`, `[[ … ]]` with an arithmetic test (`-eq -ne -lt -le -gt -ge`, bare names included) or `-v`, `(( … ))` / `$(( … ))` / `$[ … ]` / `for (( … ))` over a variable, a variable as a subscript, array-literal key, substring offset or length, or indirection (`${a[x]}`, `a[x]=2`, `a=([x]=1)`, `${a:x}`, `${@:x}`, `${a[@]:x}`, `${s: -x}`, `${!x}`, special parameters too: `${-:x}`, `${?:x}`, `${$:x}`, `${#:x}`), `${x@P}` and `PS4` under xtrace (`PS4='$(cmd)'; set -x; :`, also `set -o xtrace`, `shopt -so xtrace`, `bash -x`), and an indexed array's key over a name in an assignment builtin's array value (`declare -a x=([k]=1)`, `declare x=(…)`, `export x=(…)`; an `-A` before the value makes keys strings, one after it does not), and a quoted, escaped or expanded value the builtin re-reads as an array when its target is one, `local` included when the name is already a local array in the same function (`declare -a 'x=($(cmd))'`, `v='($(cmd))'; declare -a x="$v"`, `x=(); declare x='($(cmd))'`), which the parse cannot see. A guard must refuse these by name, as the README guard does; `[[ … ]]` and `(( … ))` that are the whole command resolve to the names `[[` and `((` so it can, and run straight into `then`/`do` they resolve to the command after them; either way their words are in `ShellCommand.evaluated`, which the README guard reads. The segmenter also splits a `[[ … ]]` on `&&`, `||` and `(`, so its operands surface as fake command names in later segments (`[[ 0 == 1 || 'a[$(cmd)]' -eq 0 ]]` names `a[$(cmd)]`): the README guard follows a `[[` to its unquoted `]]` across segments. An option a variable supplies (`[ "$op" x ]`) is read only at run time. A script with any diagnostic may hide a command (`x=$(echo a[ )` swallows the lines after it as one unterminated substitution), so treat every diagnostic as a refusal, as the README guard does, in every script `allCommands()` walks; and refuse a truncated walk, since a body past the cap is never read.

## Layout

- `src/ShellSyntax.ts` — the facade: `parse` builds a `ShellScript` from `materialize.ts`.
- `src/materialize.ts` — private (not exported from the index): lexes and materializes raw records into the Schema classes. The only module that imports `internal/lexer.ts`. `ShellSyntax.parse` and `ShellScript.allCommands` both use it, so `ShellScript` never imports `ShellSyntax` (that would be an import cycle).
- `src/ShellScript.ts` also holds `ShellCommandWalk`, `ShellNestedScript` and `ShellTruncation`, the `allCommands` result, which hold a `ShellScript` and so cannot sit in their own module without a cycle.
- `src/ShellScript.ts`, `ShellSegment.ts`, `ShellWord.ts`, `ShellWordPart.ts` (twelve part classes on a `kind` discriminant), `ShellAssignment.ts`, `ShellRedirection.ts`, `ShellHeredoc.ts`, `ShellComment.ts`, `ShellDiagnostic.ts`, `ShellCommand.ts` — one concept each.
- `src/internal/` — the engine, which imports no public module: `raw.ts` (carrier records and the literal vocabularies the public `Schema.Literals` read), `lexer.ts` (the one forward scan), `nested.ts` (the explicit-stack skip scanner for opaque bodies), `heredoc.ts` (delimiter reading and body consumption, shared by both scanners), `ansiC.ts` (the `$'…'` decoder).

## Hardening invariant

Linear time, no recursion on input depth, no throw. Specifically:

- `nested.ts` keeps nesting on a frame array; never turn it into a recursive descent. It also skips heredoc bodies inside `$(…)`, which is what keeps `it's` in a commit-message heredoc from opening a quote. Its arithmetic frames (`ARITH_SUBST`, `ARITH_GROUP`) read no heredoc and no comment, and demote to a substitution or group when the second `)` is missing. `ARITH_BRACKET` is a matched `[ … ]` (`$[`, and a subscript at any word start of command text): quotes, escapes and substitutions only, so `<<`, `#` and `)` are plain. The lexer reads a subscript only in command position, and an unclosed one is opaque to the end with `UnterminatedSubscript`, since bash reads it to EOF and rejects it.
- A top-level `((` that turns out to be two subshells sets `arithmeticFailUntil` and `heredocOffUntil`, so a megabyte of `((` is not re-scanned from every offset.
- Diagnostics are capped at 1000 plus one `DiagnosticLimitReached`.
- `bracketClose` caches its last failure so a run of `[` is linear; brace expansion is matched with a stack over per-word events. Any new lookahead needs the same treatment: ask what a megabyte of its opener costs.
- `decodeAnsiC` range-checks `\u`/`\U` before `String.fromCodePoint` (U+10FFFF), keeping an out-of-range escape as written plus an `InvalidAnsiCEscape` diagnostic.
- `ShellCommand`'s wrapper table is a `Map`, so `constructor` / `__proto__` never resolve as wrappers. Each wrapper's option table is the union of its implementations (GNU and BSD `env`, sudo 1.9, the `time` reserved word, GNU and BSD `time`), long options resolve by unique prefix as `getopt_long` does, and an unknown or ambiguous option stops with no name: a missing table entry must never turn an option's argument into the command name. So does a word the wrapper steps over, an option's separate value or an `env`/`sudo` `NAME=value` word, that may not reach it as one argv word (`mayNotBeOneWord`: an unquoted expansion, brace, glob or opaque part, or a double-quoted `@` expansion such as `"$@"`), since bash splits it and the wrapper may run a word the analyzer never sees: `env -u $v git` runs `c1` when `v` is `X c1`. A double-quoted `"$v"` or `"$*"`, a tilde and a shell assignment after `time` stay one word.
- The nested scanner's quoted-run checks (`holdsDollarOrBacktick`, `ansiCRunHoldsOpener`'s one decode of a `$'…'` run, the per-frame literal-`$` flag of a `"…"` run, and `posixReadingDiffers` for a run in double quotes, whose stack is bounded by the run) read each run once more, bounded by the run; an array key is scanned once, to its matching `]` (blanks included), and its element resumes after it.
- `ShellScript.allCommands` holds its pending substitutions on a queue, never the call stack (pinned: a child `node --stack-size=200` walks a 4,000-deep chain), parses each distinct substitution once and stops at its enforced budget (body characters at most `maxDepth` × the input, 64 MiB and 10,000 records, scripts and truncations together, at most); `__test__/ShellScript.test.ts` holds it to a linear growth ratio over a deep chain, a wide fan-out and fan-out at every depth, refuses the overlapping-substitution gadget fast, and fuzzes the budget.
- `__test__/hostile.test.ts` holds 86 one-megabyte units (a unit whose quarter-megabyte run takes under 5 ms grows until it takes 5 ms; a ratio of 10 or more is re-timed, best of three), plus one array of a megabyte of keys and one of substitutions, to a linear growth ratio and runs 3000 random shell-dense strings through span-tiling invariants. Add a unit for every new opener.
