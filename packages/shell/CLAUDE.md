# @effected/shell

A tolerant shell-syntax lexer and segmenter: `ShellSyntax.parse(input)` returns a `ShellScript` of segments (simple commands split on `&&`, `||`, `;`, `|`, `|&`, `&`, the `case` terminators and newlines), each with its words, leading assignments and redirections, and words carrying their quoting provenance as typed parts. `ShellCommand.fromSegment` resolves a segment to its command name, unwrapping `sudo`, `env`, `command`, `exec`, `nohup` and `time`. Built for agent-hook guards that must know every command a Bash tool call would run.

**Tier: pure.** `effect` is the only peer; no runtime dependency, no `node:` import, no service, no layer, `"sideEffects": false`. Never add a dependency: positions stay UTF-16 offsets, and a consumer that wants line/character uses `@effected/source` itself. `__test__/entrypoints.test.ts` pins the import set, the manifest and the export list.

**Design doc:** `@./okf/modules/shell.md`. Why a package, why not core `CommandLine`, and the contract: `@./okf/decisions/shell-syntax-package.md`. Load when: changing the contract, the part kinds, the operator set, the wrapper list or the grammar's reach.

## The contract (load-bearing, never weaken)

- **Never evaluate.** No expansion of any kind and no execution. An expansion is a marked part (`variable`, `commandSubstitution`, `arithmetic`, `processSubstitution`, `glob`, `brace`, `tilde`) with its span; bodies are opaque text.
- **Never fail.** `ShellSyntax.parse` is total and synchronous; it returns a plain `ShellScript`, not a `Result`. Input the lexer cannot finish becomes an `opaque` part to the end of the input plus a `ShellDiagnostic`. No code path may throw on any input; the property test in `__test__/hostile.test.ts` holds it.
- **Fail closed.** `ShellWord.literal` is `Some` only for bare, single-quoted, ANSI-C and expansion-free double-quoted parts. Adding a part kind means deciding whether it can be literal; the default is no. Where grammar is missing, over-split (report a command the shell might not run), never under-split. In particular never read a heredoc that may not be there: a spurious one hides the lines after it, a missed one only reports its body. A token whose meaning depends on an enclosing construct needs a test inside each construct, in both scanners, and the constructs come from the bash grammar, not from memory. For `<<` (a heredoc in command text, a shift in arithmetic) they are `(( ))`, `$(( ))`, `$[ ]` and the `[ ]` subscript of a command-position `NAME[` word; `let`'s operands are ordinary words, where `<<` is a heredoc. Command position is bash's `reserved_word_acceptable`, not a local notion: the lexer's `Follows` states carry `time -p`, `time --`, `function NAME`, `coproc NAME`, `[[ … ]]`, `((…))` and `for NAME`. `\⏎` is gone before bash tokenizes, except in a comment, single quotes, after an escaping backslash or in a quoted heredoc body: every lookahead that joins two characters goes through `skipContinuations`, in both scanners and in `heredoc.ts`. A heredoc delimiter holding an expansion opener reads no body (`ExpansionInHeredocDelimiter`), since bash rebuilds `$( … )` from its parse. A `'…'` / `$'…'` run inside `${…}`, arithmetic or a subscript (array keys included) that holds `$(` or a backtick records `QuotedSubstitutionInExpansion`: bash honours the quote to find the closer, then expands the run in a double-quoted or heredoc `${…}`, in arithmetic and in an indexed array's key. Reported in every such frame, quoted or not, rather than placed as a substitution, since the operator and quoting that keep it literal are not modelled. Honouring the quote to find the closer is bash's default mode only: POSIX mode (`set -o posix`, `POSIXLY_CORRECT`) takes a `'` in a double-quoted `${…}` for a plain character, so `echo "${x:-'}"; cmd; echo "'}"` runs `cmd`. `nested.ts` tracks per frame whether it sits in double quotes (a `"` frame sets it, command text clears it, expansion frames inherit it, the root's comes from the lexer's `inDoubleQuotes`), and a run there that the POSIX reading leaves unbalanced (`posixReadingDiffers`: a stray `}`/`]`, or an open `"`/`${`/`$[`) records `QuotedCloserInExpansion`.
- **Every substitution is reachable.** Any part that can hold a `$(…)`, backtick or `<(…)` carries `substitutions` (or `expansions`), and `ShellScript.substitutions()` names every part kind in an exhaustive switch. A new part kind that can hold one must join that switch.
- **Not `CommandLine.Word`.** The result types must never become core's execution vocabulary.

## Known limits

This was checked against GNU bash 5.3 only, with the reviewed shapes, every position of a backslash-newline in them, and a random differential fuzz. That is evidence, not proof: dash and zsh were not tested, and POSIX-mode bash only for the quote rule above. A guard must not treat `commands()` as a complete gate until these are closed. Three parser modes hide a command with no diagnostic: under `shopt -s extglob` (or an inherited `BASHOPTS`), `echo @(<<E)` and `cat <<E@(x)` read a heredoc bash does not; under `shopt -s expand_aliases` an alias body is never read (`alias c='git commit'`, then `c`); and POSIX mode is otherwise unchecked, except that it expands aliases in a non-interactive shell (`BASH_ALIASES[1]=cmd`, then `1` on the next line). So refuse `shopt`, `alias`, `set -o posix` and any write to `POSIXLY_CORRECT`, assignment tokens or not (`: ${POSIXLY_CORRECT:=1}`, `for POSIXLY_CORRECT in 1`, `select POSIXLY_CORRECT in 1`, `declare {POSIXLY_CORRECT,y}=1` each turned it on), and control the environment (an inherited `POSIXLY_CORRECT`, `BASHOPTS`, `SHELLOPTS` or `PS4`). `hash -p /path/cmd ls`, `enable -n printf` and a write to `BASH_CMDS` or `BASH_ALIASES` with any key, letter-free ones included (`BASH_CMDS[1]=/path/cmd; 1`, `BASH_CMDS=([1]=…)`), make a name run something else, the `alias` class: refuse them too (the README guard refuses any mention of `PS4`, `POSIXLY_CORRECT`, `BASH_CMDS` or `BASH_ALIASES` once quotes and backslashes are removed). A guard over `raw` text must remove `\⏎` first, as bash does: the parse joins it (`[\⏎[` is `[[`) but `raw` keeps it, so `[\⏎[ x -eq 0 ]]`, `(\⏎( x ))` and `$\⏎{!x}` slip past an unjoined pattern. Text handed to another parser is not read: `eval`, `bash -c`, `source`, `xargs`, `find -exec` and `ssh` are reported as their own name, and so are argv wrappers `ShellCommand` does not unwrap (`nice`, `timeout`, `stdbuf`, `setsid`, `doas`, `chroot`, `builtin`). Nor is text bash evaluates as arithmetic, a name or a prompt, where a quoted `'a[$(cmd)]'`, or a variable holding one, runs `cmd` (each checked under bash 5.3): `let`, `trap`, `read`, `declare -i` / `typeset -i` / `local -i`, a nameref (`declare -n`) and later assignments to an integer variable, a subscripted name given to `declare` / `typeset` / `local` with any options (`declare 'a[$(cmd)]=1'`, or a name a variable supplies, `declare "$x"`; `export` and `readonly` run nothing for it), `printf -v`, `[ -v` and `test -v`, `[[ … ]]` with an arithmetic test (`-eq -ne -lt -le -gt -ge`, bare names included) or `-v`, `(( … ))` / `$(( … ))` / `$[ … ]` / `for (( … ))` over a variable, a variable as a subscript, array-literal key, substring offset or length, or indirection (`${a[x]}`, `a[x]=2`, `a=([x]=1)`, `${a:x}`, `${@:x}`, `${a[@]:x}`, `${s: -x}`, `${!x}`, special parameters too: `${-:x}`, `${?:x}`, `${$:x}`, `${#:x}`), `${x@P}` and `PS4` under xtrace (`PS4='$(cmd)'; set -x; :`, also `set -o xtrace`, `shopt -so xtrace`, `bash -x`), and an assignment builtin's array value (`declare -a x=(['$(cmd)']=1)`, `export`, `readonly`), which the lexer splits off as a subshell. A guard must refuse these by name, as the README guard does; `[[ … ]]` and `(( … ))` that are the whole command resolve to the names `[[` and `((` so it can, and run straight into `then`/`do` they resolve to the command after them, so the guard reads the segment's words too. The segmenter also splits a `[[ … ]]` on `&&`, `||` and `(`, so its operands surface as fake command names in later segments (`[[ 0 == 1 || 'a[$(cmd)]' -eq 0 ]]` names `a[$(cmd)]`): the README guard follows a `[[` to its unquoted `]]` across segments. An option a variable supplies (`[ "$op" x ]`) is read only at run time. A script with any diagnostic may hide a command (`x=$(echo a[ )` swallows the lines after it as one unterminated substitution), so treat every diagnostic as a refusal, as the README guard does.

## Layout

- `src/ShellSyntax.ts` — the facade: calls the engine, materializes raw records into the Schema classes. The only module that imports `internal/lexer.ts`.
- `src/ShellScript.ts`, `ShellSegment.ts`, `ShellWord.ts`, `ShellWordPart.ts` (twelve part classes on a `kind` discriminant), `ShellAssignment.ts`, `ShellRedirection.ts`, `ShellHeredoc.ts`, `ShellComment.ts`, `ShellDiagnostic.ts`, `ShellCommand.ts` — one concept each.
- `src/internal/` — the engine, which imports no public module: `raw.ts` (carrier records and the literal vocabularies the public `Schema.Literals` read), `lexer.ts` (the one forward scan), `nested.ts` (the explicit-stack skip scanner for opaque bodies), `heredoc.ts` (delimiter reading and body consumption, shared by both scanners), `ansiC.ts` (the `$'…'` decoder).

## Hardening invariant

Linear time, no recursion on input depth, no throw. Specifically:

- `nested.ts` keeps nesting on a frame array; never turn it into a recursive descent. It also skips heredoc bodies inside `$(…)`, which is what keeps `it's` in a commit-message heredoc from opening a quote. Its arithmetic frames (`ARITH_SUBST`, `ARITH_GROUP`) read no heredoc and no comment, and demote to a substitution or group when the second `)` is missing. `ARITH_BRACKET` is a matched `[ … ]` (`$[`, and a subscript at any word start of command text): quotes, escapes and substitutions only, so `<<`, `#` and `)` are plain. The lexer reads a subscript only in command position, and an unclosed one is opaque to the end with `UnterminatedSubscript`, since bash reads it to EOF and rejects it.
- A top-level `((` that turns out to be two subshells sets `arithmeticFailUntil` and `heredocOffUntil`, so a megabyte of `((` is not re-scanned from every offset.
- Diagnostics are capped at 1000 plus one `DiagnosticLimitReached`.
- `bracketClose` caches its last failure so a run of `[` is linear; brace expansion is matched with a stack over per-word events. Any new lookahead needs the same treatment: ask what a megabyte of its opener costs.
- `decodeAnsiC` range-checks `\u`/`\U` before `String.fromCodePoint` (U+10FFFF), keeping an out-of-range escape as written plus an `InvalidAnsiCEscape` diagnostic.
- `ShellCommand`'s wrapper table is a `Map`, so `constructor` / `__proto__` never resolve as wrappers. Each wrapper's option table is the union of its implementations (GNU and BSD `env`, sudo 1.9, the `time` reserved word, GNU and BSD `time`), long options resolve by unique prefix as `getopt_long` does, and an unknown or ambiguous option stops with no name: a missing table entry must never turn an option's argument into the command name.
- The nested scanner's quoted-run checks (`holdsSubstitutionOpener`, and `posixReadingDiffers` for a run in double quotes, whose stack is bounded by the run) read each run once more, bounded by the run; the array-key scan is bounded by the element's end.
- `__test__/hostile.test.ts` holds 76 one-megabyte units to a linear growth ratio and runs 3000 random shell-dense strings through span-tiling invariants. Add a unit for every new opener.
