# @effected/github-actions

The GitHub Actions **runtime**: the services an action needs to talk to the runner it is executing inside — environment, inputs, outputs, state, logging, workflow commands, cache, artifacts, blob storage, tool installation, OIDC — plus the GitHub-surfaces reporting suite (`GitHubMarkdown`, `ManagedDocument`, `CheckDocument`/`CheckState`) and the two adapters that close `@effected/sbom`'s attestation contracts. Integrated tier, and the **one package in the kit with a required `@effect/platform-node` peer**: an action always compiles into a Node process on a GitHub-provided runner, so there is no second platform to abstract over. Two licences follow from that and exist nowhere else in the kit — a closed list of sanctioned `node:` imports (crypto digests, `process.kill`, the fd-level detached spawn, the zlib/stream codecs) and direct `NodeServices.layer` composition inside `ActionRuntime.layer`. Six in-kit dependencies (`github`, `glob`, `npm`, `templates`, `markdown`, `sbom`), every arrow inward.

**The line against `@effected/github`: that package talks to the API, this one talks to the runner.** `RepoRef`, `InstallationToken`, `BotIdentity` and `GitHubClient` stay canonical there; `GitHubContext`, `RunnerContext` and the workflow-command protocol are canonical here. They meet at exactly two seams, both living here: `GitHubToken` and `ActionLogger.logger`.

Task-level depth lives in the dedicated skills — `building-a-github-action` (the router), `actions-runtime`, `actions-inputs-outputs`, `actions-reporting`, `actions-state-and-secrets`, `actions-cache-and-artifacts`, `testing-actions`, `designing-an-action`. This file is the per-package surface map; go there for the build sequence.

## Import

```ts
import { Action, ActionCache, ActionInput, ActionLogger, ActionOutputs, CacheKey } from "@effected/github-actions";
```

Single entrypoint; no subpaths, and no `./testing` subpath — the doubles are statics on the services themselves.

## Feature surface

| Reach for | When |
| --- | --- |
| `Action.run` + `ActionRuntime` | the entry point of a `main`/`pre`/`post` script — compose, run, render the failure, set the exit code |
| `ActionInput` | reading anything the workflow passed in `with:` — never spell an `INPUT_` variable |
| `ActionOutputs` | `set`/`setJson`, job summary, `exportVariable`, `addPath`, `setFailed`, `setSecret` |
| `ActionState` | handing typed values from `main` to `post` through `GITHUB_STATE` |
| `ActionEnvironment` | `GITHUB_*`/`RUNNER_*` context, the event payload, debug mode, scoped env overrides |
| `ActionLogger` / `WorkflowCommand` | grouped or buffered step logging, annotations; the raw `::command::` strings |
| `Secret` | any moment a `Redacted` must become a string — the only sanctioned declassification |
| `DryRun` | rehearsing a run: every mutation goes through `guard` |
| `ActionCache` + `CacheKey` | the runner's cache, and building a key with a correct restore ladder |
| `Artifact` | uploading/downloading/listing workflow artifacts |
| `BlobStore` / `GitHubCacheBlobStore` | key→value blob storage on S3 or on the Actions cache backend |
| `ToolInstaller` / `PackageManagerInstaller` | downloading, extracting and tool-caching a binary or an exact npm/pnpm/yarn/bun |
| `GitHubToken` | minting, reading and disposing an App installation token across action phases |
| `OidcTokenIssuer` / `ActionsIdentityToken` / `ActionsProvenance` | the runner's OIDC token, and the `sbom` seam |
| `GitHubMarkdown` / `ManagedDocument` / `CheckDocument` / `CheckState` | rendering a report onto a GitHub surface and keeping it current |
| `DetachedProcess` / `ChildEnv` | spawning a worker that outlives the step, and building its `PATH` |

## Core API

### Entry point

- **`Action.run(program, options?)`** — `Promise<void>`, and it **never rejects**: the failure lands in `process.exitCode`, which is what the runner reads. Composes `ActionRuntime.layer`, renders one `::error::` line carrying `[Tag]: message` (`describeCause`, also exported) and puts the full `Cause.pretty` behind `::debug::`. It deliberately does **not** wrap the program in a log buffer — the package this replaces did, and a defect inside the buffer swallowed the whole transcript. `options.layer: Layer<R, never, ActionServices>` is how extras attach: `Action.run(program, { layer: ActionCache.layer })` compiles with no further wiring because the cache's requirements are all in `ActionServices`.
- **`ActionRuntime.layer`** — `Layer<ActionServices>` = `ActionEnvironment | ActionLogger | ActionOutputs | ActionState | NodeServices | HttpClient`. A bound constant, not a factory (layers memoize by reference). **`ActionCache`, `Artifact` and `GitHubCacheBlobStore` are deliberately excluded** — they are the only `@azure/storage-blob` importers, and folding them in would put a blob client in the bundle of every action that merely sets an output. It also installs `ActionInput.layerDefault` as the default `ConfigProvider`; **never remove it** — a live action shipped a false green because every bare `Config.string("dry-run")` fell back to its default while the runner published `INPUT_DRY-RUN`.

### Environment, inputs, outputs, state

- **`ActionEnvironment`** — reads `process.env` **once, at layer construction**, into an immutable map. Nothing else in the package reads it, and nothing mutates it, so `withEnv(overrides, effect)` is fiber-local and parallel-safe. Members: `get` / `getOptional`, `github` → `GitHubContext`, `runner` → `RunnerContext`, `isDebug`, `payload`. Layers: `layer` (needs `FileSystem`), `layerFrom(env)`. `GitHubContext.headRef` is an `Option<string>` because outside a PR the runner may write the **empty string** rather than omit `GITHUB_HEAD_REF` — both decode to `None`; use the derived `branch` getter, which owns the headRef-else-refName fallback. Honest cost of the snapshot: a variable exported mid-run by `exportVariable` is not seen by an already-seeded reader — which matches GitHub's model, where `exportVariable` targets *subsequent* steps.
- **`ActionInput`** — statics returning `Config` values, so inputs compose with the rest of Effect's config layer: `string`, `boolean`, `integer`, `redacted`, `lines`, `list`, `pairs(name, { requireValue? })`, `schema(name, codec)`. It owns the `INPUT_` mangling: GitHub uppercases and replaces **spaces**, and leaves **dashes alone** — `variable("biome-version")` is `INPUT_BIOME-VERSION`, and a hand-written `INPUT_BIOME_VERSION` reads as absent on a real runner and greens the suite against the wrong value. **A missing input and `""` are both *missing data***, so an optional input needs `Config.withDefault`/`Config.option` at the call site or the read fails. `list` splits on newlines *and* commas, strips whole-line `#` comments and a leading `-` or `*` bullet marker; `pairs` is one `key=value` per line, splitting on the **first** `=` only, rejecting an **empty key** unconditionally (a bare `=` too) and naming the offending line — an empty *value* is legitimate unless `requireValue` is set. `provider(env?)` / `layer(env?)` dual-accept **input-name** keys (`{"biome-version": "…"}`) and mangle internally, an explicit `INPUT_`-spelled entry winning; `providerOver(ambient)` is the fall-back-to-ambient form `layerDefault` installs.
- **`ActionOutputs`** — `set`, `setJson(name, value, schema)`, `summary`, `exportVariable`, `addPath`, `setFailed` (which does **not** set the exit code — `Action.run` owns that, so a reported-then-recovered failure is not doomed), `setSecret`. Runner-file delimiters are **derived, never random**: `EFFECTED_EOF` extended with `_` until absent from the value, making collision impossible rather than improbable and keeping the write deterministic under test. `layerDetached` inverts the service for a detached worker: `setSecret` a documented no-op, the runner-file members failing typed as `DetachedOutputError`, `setFailed` a plain log line.
- **`ActionState`** — `save`, `get`, `getOptional`, `saveSecret`, all schema-driven. `save` **proves the round trip at save time** — the encoded form must survive `JSON.stringify`/`parse` and re-decode, failing `notPlainJson` naming the key rather than leaving a `malformed` mystery for the `post` phase. Consequence: use `Schema.OptionFromNullOr`, never `Schema.Option`.
- **`ActionLogger`** — `group`, `withBuffer(label, effect, { onSuccess })`, `withStep(name, effect, { summary })`, `notice`, `annotated`. `withBuffer({ onSuccess: "discard" })` discards a *success* and nothing else: failure, defect and interruption all flush, and step debugging overrides the discard. `withStep` is the composition `withBuffer` alone cannot reach — discard-on-success plus **one** info line (default `✅ <name>`) emitted **outside** the buffered region, and a `❌ <name>` header through `Console`. `ActionLogger.logger` maps Effect levels onto workflow commands (`Error`/`Fatal` → `::error::`, `Warn` → `::warning::`, `Debug`/`Trace` → `::debug::`, `Info` → plain) through core `Console`, so it is observable in a test with no runner; `layerLogger` installs it.
- **`WorkflowCommand`** — the pure protocol renderer: `render`, `debug`, `notice`, `warning`, `error`, `group`, `endGroup`, `addMask`, plus `AnnotationProperties`. Zero dependencies; reach for it only when you need the string itself.
- **`Secret`** — `forChildEnv`, `forRunnerFile`, `forSigning`, `forProcessEnv`, `mask`, `adopt(name)`. **The only place `Redacted.value` appears in `src/`, and a structural test asserts it** — a new declassification case means a new member here, never an exception. Masking is the floor: every member registers the value with the runner's log filter *before* returning plaintext. `adopt` is the one scoped exception (a `Config` re-wrapping an inherited plaintext the parent already masked). Masking assumes the runner parses stdout, so **a detached worker inverts it**: the parent masks before the spawn via `forChildEnv`, and the worker composes `ActionOutputs.layerDetached`.
- **`DryRun`** — `isDryRun` and `guard(label, effect, fallback)`; the fallback is required so a rehearsal must say what it produces. `layer` reads the `dry-run` input (failing `ConfigError` on a non-boolean like `dry-run: yes`), `layerFromInput(name)` renames it, `layerFrom(enabled)` pins it.

### Cache, artifacts, blobs, tools

- **`CacheKey`** — a `Schema.Class` over `segments` + optional `restoreDepths`, with `key` and `restoreKeys` getters. `of(...segments)`, `forBranch({ scope, branch, os?, hash? })`. Three points in the restore-key policy space: absence means the default every-prefix ladder, `withRestoreDepths([...])` names how many leading segments each rung keeps (digest segments a five-segment key must not lose), `withoutRestoreKeys()` sends zero rungs for exact-match-only. **`withNamespace(segment)` is the cache-bust primitive**: the segment goes **first** and the ladder is **dropped**, because restore keys are prefix matches — fold a bust token in later and ordinary runs prefix-match the busted entries, so the cache looks healthy while serving poison. Follow with `withRestoreDepths` if you want an in-namespace ladder. `digest(input, length = 8)` is the segment-safe short digest for **non-file** segments (throws `RangeError` outside `1..64`); `hashFiles(files)` is for content and is **byte-compatible with `@actions/glob`'s `hashFiles`** — paths sorted, each file hashed alone, per-file digest fed into the accumulator as **binary**, not hex (a hex-fed accumulator yields a plausible digest that never matches anyone else's entry). `matchingFiles` and `hashMatching` pair globbing with hashing; both answer `Option.none()` when nothing matched, because "no files" is not a digest — folding it into a key caches against a constant. Errors are a per-reason union: `CacheKeyReadError` (required `path`) | `CacheKeyBadPatternError` (required `pattern`), aliased as `CacheKeyError`.
- **`ActionCache`** — `save(paths, key)` / `restore(paths, key, restoreKeys?)`, the key being a `string` or a `CacheKey`. `save` resolves its paths as globs (via `@effected/glob`, never `@actions/glob`) with `actions/cache` parity — non-matching patterns drop silently, an empty resolution fails typed — while `versionOf` hashes the **literal** pattern list on both sides, so restore resolves nothing and the versions still agree.
- **`Artifact`** — `upload(name, files, rootDirectory, options?)`, `list`, `get`, `download(artifactId, options?)`, `delete`. `ArtifactError.reason` includes `notFound` distinctly from `refused`.
- **`BlobStore` / `GitHubCacheBlobStore` / `BlobEnvelope`** — `get`/`put`/`has` over `StoredBlob<A>` (`{ metadata, body }`), backed by `BlobStore.layerS3(config)` or `GitHubCacheBlobStore.layer`. **The stored value is `StoredBlob<A>`, never `Blob<A>`** — the old name collided with the DOM global and shipped in the docs model as `Blob_2`. `BlobEnvelope.encodeResult`/`decodeResult` are sync `Result`s doing the framing; their error union is per-reason and the split earns its keep, because `NotABlobEnvelopeError` and `UnsupportedBlobEnvelopeVersionError` are ordinary cache misses on a migrating consumer while `TruncatedBlobEnvelopeError` and the metadata codec errors are corruption worth reporting.
- **`ToolInstaller`** — `find`, `download`, `extractTar`, `extractZip`, `cacheDir`, `cacheFile`, `provisionFile({ tool, version, url, binary })`. It stages under the cache root and **renames** into place, so the tool cache only ever holds complete tools — a copy-in-place leaves a partial directory that `find` reports as a hit forever. `provisionFile` packages the single-bare-binary composition (find → download → chmod `0o755`, skipped on Windows and applied *before* caching → `cacheFile`) and treats a hit missing the named binary as foreign. **`ToolInstallerError.subject` is required**; it also carries a `retryable` getter.
- **`PackageManagerInstaller`** — `install(pin: PackageManagerPin, options?)` → `AmbientPackageManager | CachedPackageManager` discriminated on `source`, every tool-cache answer carrying an `addPath`-able `binDir`. This is the only module importing `@effected/npm`.
- **`FileBlobTransfer` / `DataBlobTransfer` / `BlobTransferError`** — the transport seam. Each Azure module ships `layerWith(transfer)` beside `layer`: the protocol (RPC sequence, conflict handling, version derivation, retry, framing) is what this package owns and tests; the pre-signed `PUT` is not.

### Reporting, tokens, attestation

- **`GitHubMarkdown`** — `table`, `tableFor(schema, options)`, `heading`, `link`, `code`, `codeBlock`, `list`, `details`, `raw`. `tableFor` defines columns once from a row schema — declaration order, `title` annotations, **encoded** cell values — and **requires `format` for any field whose encoded side is not a string** rather than falling back to `String(value)`; that string-joining fallback is the live table-corruption defect this module exists to delete. `raw` is the identity function, present to *state* that a fragment is already rendered.
- **`ManagedDocument`** — `parse`/`parseResult(source)`, `region`, `entry`, `regions`, `withRegions`/`withRegionsResult(entries)`, `matches`, `sentinel`. Managed `BEGIN`/`END` regions in a document whose surrounding text belongs to someone else. **Not a second region engine** — the grammar, line-ending invariant and idempotence proof stay in `@effected/templates`. Region `meta` is always present (`{}` for a bare marker) so no reader branches on absence, and is **not addressable**: a region is found by key alone, so changing metadata updates in place.
- **`CheckDocument`** — a debounced reconciler over `CheckReport`s: `report(check, report)`, `checks`, `flush` → `written | unchanged | stale`. Writes only when the render changed; **trailing** debounce with a max-wait; the finalizer registers before the daemon forks; a failed background pass logs and keeps the registry, and **only `flush` surfaces the typed error**, because a reporting document must not fail the run it reports on. The sink is `(rendered) => Effect` or `{ write, read? }` — with `read`, each pass reconciles against the live text. `stamp` is a **per-run constant** minted at startup (per-pass "now" would defeat write suppression); `CheckDocumentStamp.isAtLeastAsRecent` is total and reflexive, so only a **strictly older** pass drops, announcing itself once at the transition. The guard narrows the race window; it does not make the write atomic — GitHub's comment API offers no conditional write.
- **`CheckState` / `projectCheckState`** — the seven-state literal (`running | pass | fail | warn | user_interaction_required | skipped | timeout`) projected to `{ status: "in_progress" }` or `{ status: "completed", conclusion }`. It **mirrors `@effected/github`'s conclusion literals structurally** so the module reaches no API client; a test pins the mirror. Never "fix" it into an import.
- **`GitHubToken`** — the one bridge to `@effected/github`. `provision(options)` is an `acquireUseRelease` whose release arm **revokes** (a retrying `pre` would otherwise leave hours of unreferenced write tokens behind); `read`, `botIdentity`, `clientLayer(options?)` and `dispose`. An installation token lives about an hour and **no later phase can re-mint one** — the credential that could is the app private key, and persisting *that* through `GITHUB_STATE` would trade an hour-long token for a permanent one. So `read` fails typed (`GitHubTokenError`, `reason: "expired"`) instead of handing back a token that answers 401; a phase that can outlive the hour calls `provision` itself. `dispose` skips an already-expired token.
- **`OidcTokenIssuer` / `OidcClaims`** — `token(audience?)` → `Redacted<string>`, `claims(audience?)` → the twelve-field `OidcClaims`. **`ActionsIdentityToken.layer`** closes `@effected/sbom`'s `IdentityToken`; **`ActionsProvenance.capture(audience?)`** closes `SlsaProvenance` and owns the OIDC-claims rename **once** — eleven all-string fields where a transposed `repository_id`/`repository_owner_id` typechecks and signs the wrong provenance. `sbom` must not depend on the Actions runtime, so the adapters live here; never add the reverse edge.

### Processes

- **`DetachedProcess`** — `spawn(options)` → core's `ProcessId`, `awaitReady(probe, options?)`, `httpProbe(url)`, `reap(pid, signal?)`, plus `ops`/`makeTestOps`. **`reap` takes a plain `number` and guards it**: the pid arrives as text from another process, `process.kill(0)` signals the caller's whole process group and `-1` everything the user owns — an unguarded reap of a state value that decoded to `0` takes down the job. `ProcessId` (the schema, decoding to *core's* brand) is the other defense, refusing the bad value on the way out of `ActionState`. Never trade the plain-number guard for a brand. Errors are a per-reason union: `DetachedLogUnavailableError | DetachedSpawnFailedError | InvalidPidError | DetachedSignalFailedError | DetachedNotReadyError`.
- **`ChildEnv`** — pure, zero-import: `pathKeyOf(base)`, `prependPath(dirs, { base, platform })` → `{ env, extendEnv: true }` as **one value** (a bare `env` replaces the child's whole environment), written through the inherited `PATH` key's own casing (Windows spells it `Path`), and `needsShell(platform)` for the CVE-2024-27980 win32 `.cmd` rule. `base` and `platform` are **required** — this module reads nothing ambient.

## Testing machinery

Every service ships `makeTest(overrides?)` + `layerTest(overrides?)`, with unstubbed members dying loudly and naming the member. Three deliberate exceptions: `ActionEnvironment` seeds the twelve `GITHUB_*` variables, `ActionLogger` defaults to silent (`layerSilent` too), `DryRun` defaults to rehearsing. `ActionEnvironment.makeTest`/`layerTest` take the payload as a **second argument**, served directly rather than through a `GITHUB_EVENT_PATH` read (`layerTest` hard-provides a noop filesystem, so seeding the path through `overrides` goes nowhere); `undefined` means *not served*, so an unarranged payload still fails typed. `OidcTokenIssuer.layerFor(claims)` returns a **real decodable** unsigned JWT built from the same claims `claims()` reports — that is what makes the provenance path reachable at all. `BlobStore.layerMemory` runs the real envelope framing. `DetachedProcess.makeTestOps` stubs the ops record. For runner-file assertions, back `ActionOutputs`/`ActionState` with a real `@effected/memfs` volume built eagerly (`makeInspectableWith` + `Layer.succeed`) and seed the runner-file directory — both write with `flag: "a"`, and a `Map` stub re-implements append by concatenation. Depth → `testing-actions`.

## Gotchas

- **No `@actions/*` package, ever.** The cache, artifact and tool-cache protocols are implemented directly against their HTTP APIs; `@actions/cache` alone drags a tree larger than this package. Globbing is `@effected/glob`.
- **The results backend only exists inside a `uses:` step.** `ActionCache`, `Artifact` and `GitHubCacheBlobStore` all speak Twirp v2 at `ACTIONS_RESULTS_URL` with `ACTIONS_RUNTIME_TOKEN`, which the runner injects into **action** contexts and **not** into `run:` shell steps. Identical code works from a bundled action and fails under `node ./main.js`; all three report `misconfigured` **naming the absent variable**, because nothing else distinguishes the two cases.
- **Four error names are per-reason tagged unions, not classes with a `reason` field** — `ActionOutputError`, `BlobEnvelopeError`, `CacheKeyError`, `DetachedProcessError`. Each name survives as a **type alias**, so no signature moved, but you match on `_tag` (and can `Effect.catchTag` a single reason) rather than on `.reason`. The remaining error classes — `ActionEnvironmentError`, `ActionStateError`, `ActionCacheError`, `ArtifactError`, `BlobStoreError`, `BlobTransferError`, `ToolInstallerError`, `PackageManagerInstallerError`, `OidcTokenError`, `CheckDocumentError`, `ManagedDocumentError`, `GitHubTokenError` — still carry a `reason`/`kind` literal.
- **`@azure/storage-blob` is confined to three modules** (`ActionCache.ts`, `Artifact.ts`, `BlobStore.githubCache.ts` — three, not two, because Twirp hands back an Azure blob URL), `@effected/markdown` to `GitHubMarkdown.ts`, `@effected/npm` to `PackageManagerInstaller.ts`. Be precise about what that buys: these are declared dependencies, so every consumer installs them and a resolver still walks them. What is proven is that **no import edge exists** from a light module to a heavy one, which with `"sideEffects": false` and module-per-file output lets a tree-shaking bundler drop it. *Droppable by construction*, not *absent by construction*.
- **Never fold `ActionCache`/`Artifact`/`GitHubCacheBlobStore` into a shared runtime layer.** Taking one costs a caller exactly one line via `Action.run`'s `layer` option.
- **`Config.withDefault` reads the *issue*, not the combinator**: an `InvalidValue` whose `actual` is `None` is classified as missing data and silently defaulted. A malformed `dry-run` input once resolved to `false` this way. Any typed `ConfigError` built here must carry its `actual`.
