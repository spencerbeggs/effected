# @effected/jsonl

Append-only, schema-validated JSONL journals as a definable Effect service. Declare the events a journal may contain, mint a service class for that registry, and read it as a filtered stream, a running projection or a single observable "current state" — while other processes append to the same file. Every line is an envelope (`at`, `event`, an optional `scope`, and a `data` payload validated by the schema you registered for that event), so the journal stays greppable, `jq`-able and diffable in a pull request while the reads that matter stay typed.

## Why @effected/jsonl

The subject here is not the *format* — one JSON value per line is a two-sentence specification and needs no library. The subject is the file as a live object: a journal that only ever grows, whose current state is its last valid line, whose tail may be torn mid-append, and which several processes read while one writes. That bundle of semantics is what consumers keep reimplementing in shell scripts, and it is what this package owns.

The naive way to consume a journal is to read the whole file and hand it to whatever asked — a model, a dashboard, a hook — which makes the cost of answering a question about the *last* line grow with the age of the file. Every read surface here takes the same filter instead. `query`, `changes` and `projection` all accept a [`Slice`](/jsonl/api/interface/slice) of events, scopes and a half-open time range, and matching runs on envelope fields, so a non-matching line's payload schema is never invoked at all. Sharing a journal with a noisy neighbour costs nothing for the neighbour's lines.

## Install

```bash
npm install @effected/jsonl effect
```

```bash
pnpm add @effected/jsonl effect
```

Requires Node.js >=24.11.0. `effect` v4 is the only peer dependency, and the only dependency of any kind.

`FileSystem` comes from `effect` core rather than from a platform package, so you provide it once at the edge — `NodeFileSystem.layer` from `@effect/platform-node` on Node. `Path` is deliberately *not* required: every journal path is an opaque string handed straight to `FileSystem`, and this package never joins, resolves or splits one.

## Quick start

Declare the events, then define a service class for that registry with the journal's `config` beside it. `at` is stamped by the service from the Effect `Clock` — never by the caller — so two writers cannot disagree about ordering, and `TestClock` controls it exactly in tests:

```ts
import { Journal, JsonlEvent } from "@effected/jsonl";
import { NodeFileSystem } from "@effect/platform-node";
import { Effect, Option, Schema } from "effect";

const Started = JsonlEvent.make("started", {
  data: Schema.Struct({ round: Schema.Number, phase: Schema.String }),
});
const MailReceived = JsonlEvent.make("mail-received", {
  data: Schema.Struct({ from: Schema.String, subject: Schema.String }),
});

const events = [Started, MailReceived] as const;

class MailJournal extends Journal.Service<MailJournal>()("docs/MailJournal", {
  events,
  config: { path: ".claude/mailbox.jsonl" },
}) {}

const program = Effect.gen(function* () {
  const journal = yield* MailJournal;

  // File lifecycle is explicit: an append never creates the journal for you.
  yield* journal.create;

  yield* journal.append("started", { round: 7, phase: "waiting" });
  yield* journal.append("mail-received", { from: "silk", subject: "round 7" }, { scope: "reviewer" });

  const latest = yield* journal.latest;
  return Option.isSome(latest) ? latest.value.event : "(empty journal)";
});

Effect.runPromise(program.pipe(Effect.provide(MailJournal.layer), Effect.provide(NodeFileSystem.layer)));
// "mail-received"
```

`MailJournal.layer` is a static value on the class, so providing it in several places provides one journal — one write permit, one watcher, one set of subscribers. `config` can also be an `Effect` that produces the record, for a path read from `Config` or another service when the layer builds; a path known only at run time goes through `MailJournal.make(config)` instead.

## One slice vocabulary, on every read surface

[`Slice`](/jsonl/api/interface/slice) is `events`, `scopes`, an inclusive `from`, an exclusive `to`, a `cursor` to resume from, and `onInvalid` for lines that cannot be decoded. The same object filters a historical [`query`](/jsonl/api/interface/journalshape), a live `changes` subscription and a running `projection`, so a consumer who can express a subscription can express a query without translating. Passing a literal `events: ["mail-received"]` narrows the stream's element type to exactly that variant, which makes a projection over a slice exhaustively checkable rather than a cast.

Two costs are worth stating exactly rather than leaving to be discovered. `latest` — and every `lastValid`-backed read — is a **bounded tail window** that widens only when it has to, so "what is the current state" never costs the history. A **historical** `query` is **paged**: it reads its region a bounded page at a time and emits each page's matches before reading the next, so memory is a page plus the longest line, whatever the journal's size, and a consumer that stops early stops the reading. A `cursor` — an envelope's `position.end`, persisted — is what keeps the read the size of the remainder rather than the file.

A line that cannot be decoded is **skipped** by default (`onInvalid: "skip"`), so a journal shared with another writer, or with an older or newer version of your own application, stays readable. Pass `onInvalid: "fail"` when a hole in the history must stop the read.

## The pure core needs no runtime

The read path works without an Effect runtime at all. [`Line`](/jsonl/api/class/line) and [`Envelope`](/jsonl/api/variable/envelope) are synchronous and `Result`- or `Option`-returning, so a `PreToolUse` hook or a shell-adjacent script can walk back to the last valid envelope with no layer graph to build:

```ts
import { Envelope } from "@effected/jsonl";
import { Option } from "effect";
// The same registry the writer declared, exported from your own module.
import { events } from "./events.js";

declare const tailText: string; // a window read from the end of the file, starting at a line boundary
declare const tailStart: number; // the byte offset that window starts at in the file

const current = Envelope.lastValid(events, tailText, tailStart);
if (Option.isSome(current)) {
  current.value.event; // the tag
  current.value.position.end; // its byte offset in the file, for a resumable cursor
}
```

"Last valid" always means the last valid **envelope**, never merely the last valid JSON. That distinction is what catches a torn tail: an envelope is always an object, and every strict prefix of an object's text is invalid JSON — whereas a torn scalar (`42` cut mid-write leaves `4`) parses cleanly as a different value that no walk-back over raw JSON can detect.

## What the cooperative-writer contract actually guarantees

The service watches the journal file for the life of its layer scope and tracks the byte offset of everything it has decoded, so an append by another process — a sibling service, a shell script, a human with `>>` — arrives at your subscribers through the same stream as a local one. Nothing about the mechanism is a lock, and the guarantees are narrower than "it just works":

- **The contract is a discipline, not an enforced guarantee.** Every writer sharing a journal issues one `writeAll` of a complete, `\n`-terminated line to a handle opened `{ flag: "a" }` (`O_APPEND`). There are no advisory locks, because a lock would only be honoured by writers who had already agreed to cooperate.
- **Atomicity is an OS property of `O_APPEND` at reasonable line sizes**, not an API guarantee. Keeping payloads bounded is part of the contract rather than an optimization.
- **A torn tail is tolerated; truncation or replacement is surfaced, not hidden.** An unterminated fragment is walked over and the offset holds until the line completes. If the file shrinks or is replaced underneath a reader, that is a broken contract: every live subscriber's stream ends with a typed [`JournalResync`](/jsonl/api/class/journalresync), and the journal itself re-adopts the file as it now is, so its own `latest` and later appends keep working. Subscribers re-read from the start.
- **A missing journal is a legal state.** Building a layer over a path that does not exist yet produces a working service that starts watching once the file appears. `create` and `remove` stay explicit, so a typo in a path never materializes a second, empty journal that looks like a working system with no history.

## Errors

Eight tagged errors, one recovery each, routed with `Effect.catchTag`: [`MalformedLine`](/jsonl/api/class/malformedline), [`UnknownEvent`](/jsonl/api/class/unknownevent), [`InvalidData`](/jsonl/api/class/invaliddata), [`UnserializableData`](/jsonl/api/class/unserializabledata), [`TerminalViolation`](/jsonl/api/class/terminalviolation), [`JournalClosed`](/jsonl/api/class/journalclosed), [`JournalNotFound`](/jsonl/api/class/journalnotfound) and [`JournalResync`](/jsonl/api/class/journalresync). Each operation's error channel names only the tags it can raise — [`AppendError`](/jsonl/api/type/appenderror) for `append` and `appendPatch`, [`QueryError`](/jsonl/api/type/queryerror) for `query`, [`ChangesError`](/jsonl/api/type/changeserror) for `changes` and `projection` — so an exhaustive `catchTags` never handles an impossible tag. The three line-level failures, collected as [`DecodeError`](/jsonl/api/type/decodeerror), reach a read only when its slice sets `onInvalid: "fail"`. Causes — a schema issue, a `JSON.stringify` throw — are carried structurally rather than stringified, so `error.issue` and `error.cause` keep their shape. Core's `PlatformError` is deliberately not a member of the union: IO failures pass through untranslated.
