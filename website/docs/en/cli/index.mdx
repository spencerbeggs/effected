# @effected/cli

The presentation boundary of a command-line program built on `effect/cli`. It covers who the output is for and how it reaches them: plain log lines on the right stream, colour and links only where the terminal and the reader can use them, documents rendered for a person, an agent or a CI log, failures reported through your own logger with the right exit code, prompts that know when there is nobody to ask, and interactive screens and live views drawn with Ink. `effect/cli` still owns argument parsing, flags, the command tree and help. This package adds no parser and no command model.

## Why @effected/cli

Everything here shares one property: **you only discover you needed it by shipping bad output to a person or a machine.** None of it fails a type-check, a test, or a review of the code in isolation.

Effect's default logger emits `[00:33:56.619] INFO (#2): message`, which is right for a service and noise for a tool someone is watching. A platform `runMain` reports an unhandled failure through that same default logger, outside the layers your program was given, so it prints on **stdout**, the one stream errors must not use. Colour codes end up in an agent's context window or a CI log. A prompt fires inside a pipe and hangs. A file name containing `::error::` becomes a workflow command in GitHub Actions. And a decode failure arrives as a structured tree when what a user needs is a sentence naming the key they got wrong.

This package makes those decisions once, at the edge of the program, from the environment it actually runs in, so the code that prints does not have to make them.

## Install

```bash
npm install @effected/cli @effected/env @effected/glob @effected/walker effect
```

```bash
pnpm add @effected/cli @effected/env @effected/glob @effected/walker effect
```

Requires Node.js >=24.11.0. `effect` v4, [`@effected/env`](/env), [`@effected/glob`](/glob) and [`@effected/walker`](/walker) are peer dependencies. `@effected/env` supplies the audience and terminal services, and `walker` (with its `glob` peer) finds the project root for editor links. The package's one runtime dependency is [`@effected/github-commands`](/github-commands). It never imports a platform package, so it runs unchanged on Node, Bun and Deno.

Three peers are **optional**:

- `ink` and `react`, with `@types/react` for TypeScript, are needed only for the interactive screens and live views in `@effected/cli/ui`. The package root never reaches them, and importing `./ui` loads neither until a screen first mounts.
- [`@effected/config-file`](/config-file) is needed only by [`ConfigIssueRenderer`](/cli/api/class/configissuerenderer).

```bash
npm install ink react @types/react
```

## Four entrypoints

- **`@effected/cli`** is the presentation layer: audience, theme, messages, documents, renderers, links, failure reports, logging, prompts and the runtime. It loads no React.
- **`@effected/cli/ui`** holds the interactive screens drawn with Ink: `CliUi.run`, `prompt`, `fallback`, `live` and `context`, the widgets (`Select`, `TextInput`, `MultiSelect`, `Confirm`, `Toggle`, `Tabs`, `Viewport`), the key layer, the theme bridge, `DocView` and `UiProvider`.
- **`@effected/cli/testing`** is `CliTest`, which spawns a built bin hermetically, and `TestTerminal`, which drives core's prompts in a test.
- **`@effected/cli/ui/testing`** is `CliUiTest`, which mounts a screen, a display-only element, a whole program's screens or a live view on in-memory streams.

Nothing reachable from the root imports a testing entrypoint, so a CLI's runtime bundle never carries test machinery.

## Quick start

The one wiring: share the audience flags on the root command, run it through `CliAudience.run`, and hand that to `CliRuntime.main` with an `env`:

```ts
import { CliAudience, CliMessage, CliRuntime, Doc } from "@effected/cli";
import { NodeRuntime, NodeServices } from "@effect/platform-node";
import { Effect } from "effect";
import { Command } from "effect/cli";

const sync = Command.make("sync", {}, () =>
  Effect.gen(function* () {
    yield* CliMessage.info("syncing 2 repositories");
    yield* Doc.print([
      Doc.table(
        [{ header: "Repository" }, { header: "Files", align: "right" }],
        [
          ["acme/widgets", "12"],
          ["acme/gadgets", "3"],
        ],
      ),
    ]);
    yield* CliMessage.success("synced 2 repositories");
  }),
);

const root = Command.make("tool").pipe(Command.withSharedFlags(CliAudience.flags()), Command.withSubcommands([sync]));

NodeRuntime.runMain(
  CliRuntime.main(CliAudience.run(root, { version: "1.0.0" }), {
    platform: NodeServices.layer,
    env: { audienceEnvVar: "TOOL_AUDIENCE" },
  }),
);
```

```text
$ tool sync
ℹ syncing 2 repositories
Repository    Files
------------  -----
acme/widgets     12
acme/gadgets      3
✓ synced 2 repositories
```

At a colour terminal the glyphs are painted and the header is bold. In a pipe, for an agent (`--agent`, or an agent detected from the environment), or under `NO_COLOR`, the same program writes no escape sequence of any kind. Under GitHub Actions, anything the runner could read as a workflow command is neutralized. A failure anywhere renders as a short report on stderr, with a non-zero exit. The [getting-started guide](/cli/getting-started) builds this up step by step.
